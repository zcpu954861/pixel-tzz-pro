# 里程碑 3A 实机验收集中修复清单

- 状态：集中修复、完整自动检查、逐项多客户端实机回归与压力边界均已通过
- 验收世界：`3A V1`
- 适用版本：`Pixel-Tzz-Pro 0.1.0` 的 V3A 玩家终端阶段

## 1. 收口原则

- 本文只记录 3A 正式实机验收中确认的问题与已经明确的修复方向。
- 模组继续只提供可复用框架；任务文案、公开字段、受众、历史内容和帮助内容仍由数据包注册。
- 玩家端中文是主信息，英文只作为低亮度辅助。
- 未授权的任务、时间、个人字段和历史数据不得发送到客户端；乱码或空状态只是安全投影之后的表现。
- 普通终端与全部模组自有页面使用固定构图。不同窗口和 GUI 缩放只整体等比适配，不改变页面信息架构。
- 只有明确指定的正文、数据、时间线和详情区域可以独立滚动；顶栏、底栏和核心操作始终固定。
- 本轮修复完成前不提交、不推送；全量自动化通过后仍由用户进行实机回归。

## 3. 集中修复项

### 3A-F01 固定构图与有上限的等比缩放

现象：

- 小窗口或较大 GUI 缩放触发紧凑断点后，原有卡片被重排成缺少正文的横条；
- 控件位置、页面层级和玩家已经建立的空间记忆被破坏。

要求：

- 普通玩家终端以已经验收的 `620×340` 逻辑外壳为母版；主持人控制台、全部子页面、二次确认、强制流程页、受限暂停页与安全错误页以同一验收环境对应的 `640×360` 逻辑画布为母版；
- 按可用宽高统一计算缩放，保持宽高比、换行、控件相对位置和动画方向；
- 小屏整体缩小且核心按钮完整可达；
- 大屏达到主题配置的最大画布尺寸后停止放大并居中；
- 宽高比不匹配时保留边距，不拉伸也不启用结构性响应式重排；
- 页面本体、字体、导航动画、点击区域、拖动距离、裁剪和滚动条使用同一变换；背景遮罩仍覆盖实际全屏。
- 数据驱动页面即使在 2K 母版中不需要额外内容压缩，小窗口下也必须继续乘上外层画布缩放；不能出现外壳已缩小而内部正文保持原尺寸的情况。
- 玩家终端请求已发出、或权威终端实例已经到达但当前 Screen 尚未完成首轮初始化时，只显示中性的终端加载外壳；不得先渲染红色安全错误页。

### 3A-F02 当前任务页信息架构

现象：

- “过去事件 / 个人信息 / 终端帮助”占据独立内容行，压缩任务正文和本局数据；
- 右侧数据区空间不足；
- 公开进度条的填充、轨道和分段外框越过父卡片边界。

要求：

- 三个普通目的地按钮移入底部紧凑导航组；
- “退出终端”保持底栏左侧，OP 认领/接管保持底栏右侧；
- 没有公开进度时，任务正文与数据包注册的本局数据使用安全双列布局；
- 存在公开进度时，任务正文和进度组件切换为整行布局，不再为本局数据或出生点预留右栏；
- 两种布局由示例数据包在页面条件中按自己的任务 ID 选择，模组不硬编码具体任务 ID；
- 跨列卡不能用自身自然宽度反向扩张数据包声明的固定网格轨道；`328 + 8 + 224` 必须始终保持为 560 逻辑像素；
- 进度组件严格遵守父容器内容宽度和裁剪；
- 逃走者和猎人继续拥有各自语义色，页面结构保持一致。

### 3A-F03 数据可见性与乱码占位

要求：

- 数据包可以分别决定逃走者和猎人是否获准看到当前任务、全局计时、环节计时、剩余时间和任务统计；
- 未授权值不进入客户端；
- 对于数据包明确声明“存在但遮蔽”的字符串展示，页面可使用原版乱码表现，而不是空白或真实值；
- 乱码表现不能成为隐藏任务或字段是否存在的探针；
- 右侧数据项的名称、顺序、格式和可见条件由数据包页面与安全数据源共同定义。
- Tick 时间保持整数权威值，在文本模板显示层格式化为 `MM:SS` / `H:MM:SS`，页面不拼接原始 `tick` 单位。

### 3A-F04 玩家历史时间线与默认选择

现象：

- 初次打开历史页没有默认选择，右侧显示红色“记录无法查看”；
- 失效选择不会自动回退；
- 原始 `T+1165 tick` 不适合作为玩家文案。

要求：

- 初次打开默认选中最新一条当前合法记录；
- 当前记录失效时自动选中下一条最近合法记录；
- 只有确实没有记录时显示正常空状态，初次打开不显示错误；
- 底层继续使用 Tick 排序，玩家展示为“开局后 00:58”“赛前阶段 · 任务开始后 00:58”等可读时间；
- 长时间支持小时格式。

### 3A-F05 历史来源与详情布局

要求：

- 数据包可以选择左侧显示逐条公开事件，或只显示已经过去的任务汇总；
- 任务模式一项对应一个过去任务，不要求数据包伪造普通事件；
- 逃走者与猎人可以使用不同受众；
- 右侧公开正文不得越过裁剪区或屏幕；
- 游戏时间、任务、触发者、统计和结果合并进一个记录信息容器；
- 容器内部字段由数据包声明，空间不足时自动换到下一行；
- 左侧时间线与右侧正文分别独立滚动。

### 3A-F06 游戏结束与全局回顾

现象：

- 时间线结束时，已打开页面先出现“页面数据已失效”和记录错误；
- 结束后 ESC 入口直接打开逐条“过去事件”，信息层级弱于既有全局回顾。

要求：

- 时间线结束时，已打开的普通终端播放一次正常退出动画并退回 ESC；
- 退出后显示一次非错误通知：“本局任务线已结束，赛后回顾已生成”；
- ESC 入口立即刷新为赛后回顾；
- 玩家主动打开后进入既有全局回顾，逐条过去事件作为回顾内的深入入口；
- 主持人继续进入主持人控制台并从控制台打开全局回顾；
- 不自动强制弹出普通回顾页面。

### 3A-F07 注册选项显示名称

现象：

- 个人信息正确显示数据项名称“猎人出生点”，但值显示内部键 `north_gate`。

要求：

- 框架为已授权的选择值投影数据包注册的选项显示名称；
- 页面显示“北门”等名称，不暴露内部键；
- 不在页面 JSON 中硬编码值到中文的映射；
- 值被取消授权、删除或预算淘汰时，显示名称必须一起消失；
- 原始值仍在但显示名称因预算缺席时，只能显示固定安全状态，不得回退暴露机器键。

### 3A-F08 “安全操作”正文页重构

现象：

- 正文页重复显示轮播封面才需要的文档图标；
- 顶部只占半幅并留下大片空白；
- 步骤区高度过大；
- 检查和结果区域被固定底栏裁切；
- 成功提示覆盖按钮并形成重叠外框。

要求：

- 删除正文页文档图标；
- 使用紧凑全宽标题和低亮度辅助英文；
- 保留真实的 `01 → 02 → 03` 执行顺序，但压缩为窄步骤轨；
- 检查说明和执行结果完整位于底栏上方；
- 操作按钮始终完整可见并成为主操作；
- 成功、冷却和失败使用独立紧凑反馈，不覆盖按钮、不插入新页面。

### 3A-F09 `/reload` 页面恢复

现象：

- `/reload` 后数据正确保留，但普通终端被无条件退回玩家首页。

要求：

- 旧 page instance、序列和按钮令牌必须失效；
- 若当前页面、来源动作、受众和路由在新 generation 中仍合法，创建新实例并无感恢复当前页面；
- 合法页面栈、帮助选中项和历史选中项尽量恢复；
- 只有页面删除、权限变化或路由变化时才退回最近合法父页；
- 不恢复任何旧的可执行令牌。
