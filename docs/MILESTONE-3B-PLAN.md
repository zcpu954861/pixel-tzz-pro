# V3B：动态文本与统一文字演出实施计划

状态：**产品要求与运行语义已确认；资源与编译契约已冻结，网络协议已升至 v12；运行时集成和实机验收进行中**

适用基线：

- Minecraft：`26.2`
- 当前模组版本：`0.1.0`
- 当前游戏 API：`api_version: 3`
- 当前网络协议：v12
- 当前客户端播放计划：FORMAT 2
- 当前世界状态：Schema v4

## 0. 文档职责

本文是 Pixel TZZ Pro V3B 的正式需求与实施计划，记录动态 Chat、Title、Subtitle、ActionBar
及其统一调度能力的已确认产品语义、权限边界、异常恢复、实施顺序和验收门槛。

本文不是已经实现的功能清单。已经冻结的精确资源字段、默认值、上限、协议版本和完整示例见
[`DATA-PACK-MESSAGE-API-3B.md`](DATA-PACK-MESSAGE-API-3B.md)。本文中的示意字段名用于固定
产品语义；若与 API 文档的可解析格式不一致，以 API 文档为准。实现状态和 Minecraft 实机
行为必须明确区分，不能把已完成静态接线但尚未实机验收的能力提前当作稳定兼容承诺。

总需求见 [`REQUIREMENTS.md`](REQUIREMENTS.md)，V3 总体分段和统一质量基线见
[`MILESTONE-3-PLAN.md`](MILESTONE-3-PLAN.md)。V3A 已完成的玩家终端、可信字段、页面操作、
权限投影和历史详情仍是 V3B 的基础能力，不能在 V3B 内复制第二套实现。命令、预览与诊断
入口已经接线，但在多客户端实机验收完成前仍不能视为稳定兼容承诺。

## 1. 阶段目标与范围

V3B 建立一套“先注册、后调用”的统一文字演出系统：

1. 数据包按稳定资源 ID 注册一套完整文字演出；
2. 一个演出可以打包多个 Chat、Title、Subtitle、ActionBar 内容；
3. 同一调用可以同时或按时间线依次播放多个内容；
4. 模组统一处理动态字段、动画、声音、受众、同步、队列、恢复和降级；
5. 数据包通过一条受控调用触发整套演出，不再手写逐 Tick 字符函数；
6. 服务端保持受众、参数、回调和游戏状态的最终权威；
7. 普通玩家最终看到的是完整、稳定、可访问且与原版行为兼容的文字体验。

V3B 明确不包含：

- 任意坐标的常驻 HUD、图标、面板和实时数据组件；这些属于 V3C；
- 通用镜头、路径、关键帧镜头和碰撞安全；这些属于 V3D；
- 致死拦截、捕获、旁观、存活统计和复活；这些属于 V3E；
- 把正式任务、剧情或游戏文案硬编码进模组；
- 任意客户端脚本、任意客户端文本、第二套绑定表达式或第二个游戏状态执行器。

## 2. 核心资源模型

### 2.1 演出 ID

V3B 的调用单位是一条“文字演出”，而不是单独的一行文本。

一条稳定资源 ID 可以包含：

- 一个或多个 Chat 内容；
- 一个或多个 Title 内容；
- 一个或多个 Subtitle 内容；
- 一个或多个 ActionBar 内容；
- 独立声音节点；
- 服务端时间线回调；
- 历史事件联动；
- 每个内容自己的延迟、时长、动画、受众和冲突策略。

所有内容默认从演出起点同时开始。数据包可以为任意节点设置独立延迟，因此同一 ID 既能完成
简单的同步提示，也能完成一段有限、确定的短文字演出。同一通道可以出现多个按序内容。

### 2.2 数据包目录

V3B 采用“一项一文件”的资源注册方式：

```text
data/<namespace>/pixel_tzz_pro/text_effects/<path>.json
data/<namespace>/pixel_tzz_pro/message_cues/<path>.json
```

- `text_effects` 注册可复用的动画、光标、颜色、声音和默认时序；
- `message_cues` 注册可调用的完整文字演出；
- 允许使用子目录组织大型数据包；
- 一个文件对应一个稳定资源 ID；
- V3B 动态字段引用 V3A 已有可信字段与绑定能力，不复制第二套数据源；
- 首版不建设难以追踪的跨文件继承链，只允许明确引用动画预设和现有字段资源。

多个数据包注册相同资源 ID 时遵循 Minecraft 数据包优先级。高优先级文件完整覆盖低优先级
同 ID 文件，不做字段级隐式深度合并。诊断工具必须显示最终资源来源和被覆盖来源。

### 2.3 动画预设与单条覆盖

数据包可以注册统一预设，例如普通通知、成功、警告、紧急、任务开始和任务结束。每个内容块
可以引用预设，并单独覆盖：

- 打字速度；
- 颜色；
- 停留与退出时间；
- 声音；
- 光标；
- 动态字段取值方式；
- 冲突、屏幕和降级策略。

模组只提供动画原语和中性安全回退，不硬编码正式游戏的视觉风格。

### 2.4 API 兼容

V3B 是 V3A 的增量扩展：

- 现有 `api_version: 3` 数据包无需修改即可继续加载；
- 不注册 V3B 资源时，行为与 V3A 相同；
- 新资源类型拥有自己的格式版本；
- 新网络负载需要递增网络协议；
- 只有启用持久化演出的世界才需要新增状态结构和迁移；
- 不因为阶段名称机械地把整个游戏 API 升到 v4。

## 3. 输出通道

### 3.1 Chat

动态 Chat 必须真正进入原版聊天历史：

1. 客户端插入一个真实逻辑聊天条目；
2. 动画帧原地更新这一条目；
3. 普通玩家聊天可以把它向上顶，动画不会中断；
4. 条目滚出可见区域后，状态仍能有界地完成；
5. 动画结束后保留最终文本；
6. 不用每帧新增消息伪造动画；
7. 不修改、不延迟、不重新签名普通玩家聊天。

动态 Chat 遵守原版聊天可见性、缩放、透明度、背景、聊天延迟和容量。玩家隐藏聊天时，模组
不能强行覆盖显示；需要强提醒的数据包应在同一演出内注册其他通道。聊天容量淘汰后的长期
记录由 V3A 过去事件或赛后回顾承担，V3B 不维护第二份隐藏永久聊天历史。

### 3.2 Title、Subtitle 与 ActionBar

V3B 提供原版语义位置上的受控文字演出，并允许配置：

- 对齐；
- 安全范围内的偏移；
- 最大宽度；
- 多行间距；
- 进入、停留和退出；
- 与其他 V3B 内容的冲突策略。

V3B 不允许借这些通道建立任意自由坐标 HUD。复杂锚点、常驻面板和实时组件留给 V3C。

### 3.3 发言者

动态 Chat 可以选择注册系统、旁白、真实玩家或已注册实体作为视觉来源，但该能力默认关闭。

- 未注册发言者时使用普通系统演出；
- 真实玩家只能使用服务端验证的真实档案和皮肤；
- 演出必须保持系统消息身份，不能伪造成签名玩家聊天；
- Chat Heads 等装饰模组可以根据保留的原版条目元数据显示头像；
- 普通系统演出没有玩家发送者时不显示头像属于正常行为。

## 4. 文本组件、参数与可信数据

### 4.1 原版富文本

V3B 文本建立在原版文本组件能力之上，而不是重新发明残缺字符串格式。必须支持当前版本中
适用的：

- `text`；
- `translate` 与参数；
- `score`；
- `selector`；
- NBT/Data，以及来自 `storage`、实体或方块的数据；
- `keybind`；
- 子组件、颜色、字体和原版样式；
- `hover_event`、`click_event` 和 `insertion`。

动画期间只有已经显示的字符具有交互，未显示内容和光标没有不可见点击区域。交互事件只保留
原版权限与确认规则，V3B 不提升玩家权限。

普通 `tellraw`、普通系统消息、签名玩家聊天和 2B 页面静态文本不会自动获得动画。只有显式
调用 V3B 演出 ID 的内容进入调度器。

### 4.2 具名参数

每个演出可以注册有类型的具名参数，例如玩家、数字、时长、任务、普通文本或受限文本组件。
每个参数声明：

- 类型；
- 是否必需；
- 默认值；
- 可信来源；
- 缺失或错误时的降级内容；
- 是否参与重复调用去重键；
- 允许使用的内容块和受众。

参数来源可以是：

- 调用时显式提供；
- 当前执行者、调用原点或目标玩家；
- Scoreboard；
- Storage；
- 当前游戏、阶段、任务、统计、事件；
- V3A 已注册并获准投影的个人字段。

服务端负责类型检查和授权。缺失参数不能把 `{player}` 等内部占位符直接显示给玩家。

### 4.3 动态字段取值时机

每个内容块可选择以下取值模式：

1. `on_display`
   - 内容块开始显示时一次性取得全部动态字段；
   - 后续整段使用同一份值。
2. `on_first_field`
   - 静态前缀可以先播放；
   - 第一个动态字段的光标出现前 1 Tick，一次性取得全部动态字段；
   - 随后全部锁定。
3. `per_field`
   - 每个动态字段在自己的光标出现前 1 Tick 取得当时最新值；
   - 该字段一旦开始显示便永久锁定；
   - 后续字段仍可取得更新后的值。

取值和显示之间不能出现旧值闪烁、空占位或额外可见停顿。

同一个字段在同一内容块内重复引用时默认共享第一次锁定值。跨通道引用分为：

- 演出级字段：所有内容共享同一份值；
- 内容块局部字段：各内容按自己的时间重新获取。

需要同一数据源在后文重新取值时，数据包使用不同字段实例，不让一句话内的同名字段无意前后
不一致。

### 4.4 条件分支

一个演出 ID 可以根据服务端状态选择内容：

- 内容块可声明受限 `when` 条件；
- 同一位置可声明按顺序匹配的多个变体，使用第一项命中结果；
- 条件可读取身份、阶段、任务、Score、Storage 和已注册字段；
- 数据包可选择在演出开始、内容块开始或字段取值前判断；
- 分支只在服务端执行，客户端只收到最终命中的内容；
- 不新增 JavaScript、任意表达式或第三套条件运行时。

复杂世界逻辑仍由数据包函数完成。

### 4.5 多语言

V3B 支持原版翻译组件和数据包声明的语言变体：

- 每个内容必须具有明确回退；
- Score、NBT、玩家名等服务端字段仍按注册时机锁定；
- 客户端按自己最终看到的译文长度播放；
- 服务端回调不信任客户端报告的文字长度；
- 多语言内容的标准结束时间使用固定总时长或所有已声明语言中的最长时长；
- 需要多人严格同步时优先使用固定总时长。

## 5. 动画与排版

### 5.1 首版动画原语

V3B 首版提供可组合、可限额的：

- 多行打字机；
- 可配置光标；
- 透明度渐入、停留、渐出；
- 逐字颜色填充；
- 颜色渐变；
- 原版乱码逐字解码为正文；
- 分段延迟和重点词停顿；
- Title、Subtitle、ActionBar 的轻微滑入或缩放；
- 指定片段的单次脉冲强调。

强烈抖动、持续旋转等影响阅读的效果不作为首版重点。效果组合数量必须受复杂度上限约束。

### 5.2 打字光标与新字颜色

打字机分别注册：

- 光标块字符，例如 `█` 或 `▌`；
- 光标颜色；
- 是否闪烁；
- 闪烁速度；
- 是否禁用光标；
- 字符刚显示时的新字颜色；
- 新字保持临时颜色的字符距离；
- 恢复为最终注册颜色时采用瞬间切换或渐变。

光标块和新字颜色是两个独立概念。字符离开临时颜色范围后必须恢复其自身最终组件样式，不能
统一覆盖原有多色、渐变或局部样式。

### 5.3 时间单位

所有时间必须带明确单位，例如：

- Tick：`10t`；
- 秒：`1.5s`；
- 毫秒：`80ms`。

不接受含义模糊的裸数字。视觉动画可以使用小于 1 Tick 的平滑时间；服务端回调向后对齐到
最近完整 Tick，绝不提前。打字速度可以使用每字符时长或每秒字符数。

### 5.4 预排版与溢出

动态文本必须避免随着字符增加反复挤动已经显示的行：

- 显式换行始终保留；
- 自动换行使用客户端真实字体、窗口和 GUI 缩放；
- 已解析但尚未显示的字符使用不可见布局提前占位；
- `per_field` 的未来字段可以注册预计宽度、最大字符数或最大行数；
- 超出预留空间时由数据包选择换行、整体缩小、截断省略或静态降级；
- Chat、Title、Subtitle、ActionBar 可以分别配置宽度与溢出策略；
- 字符计数使用可见字素单元，不拆坏中文、Emoji 或组合字符。

## 6. 声音时间轨

声音是演出的正式时间轨，支持：

- 开始音；
- 关键帧音；
- 结束音；
- 指定内容块的字符音；
- 每若干字符播放一次；
- 跳过空格、标点或换行；
- 音量、音调、声音类别；
- 可配置音调变化；
- 与文字无关的定时声音节点。

同一演出的多个通道不会自动同时播放字符音。数据包必须明确主声音轨，防止 Chat 与 Subtitle
并行时出现重复声音。演出被替换或取消后，未播放的声音节点同步取消，已经播放的声音不倒放。

讲述人只朗读稳定最终文本一次，不朗读光标和逐帧内容。

## 7. 时间线、同步与时钟

### 7.1 多人起点

每个演出可以选择：

- `immediate`：客户端收到后立即开始；
- `synchronized`：服务端选择短暂未来 Tick，目标客户端缓存后同时开始；
- `per_player`：每名玩家满足自己的屏幕条件后开始。

全体演出默认使用同步起点，个人提示默认按玩家开始。同步等待有短上限，不能因为单个高延迟
玩家长期阻塞全体。数据到达过晚的客户端跳到标准时间线正确帧，不从头慢半拍。声音与文字
共享同一时间锚点。

同步 `STATIC_FINAL` 只是当前客户端投影的静态降级，不代表逻辑实例被取消。最终投影或静态
降级无法安全发送时，只清理该物理连接上的投影；服务端权威时间线与 callback 账本继续结算。

### 7.2 时间基准

每个演出可以选择：

- `game_time`：按游戏 Tick 推进，服务器卡顿或游戏暂停时同步变慢；
- `presentation_time`：按单调现实时间播放，回调在到期后的第一个服务端 Tick 执行。

带权威流程回调的演出默认使用游戏时间；纯提示默认使用表现时间。客户端低 FPS 时直接计算
当前正确帧，不逐帧补播。

### 7.3 内容驱动与固定时长

默认打字时长按每名目标玩家实际解析的可见字符数量计算：

- 每名玩家拥有服务端计算的标准进度；
- `on_complete` 可以按该玩家的标准完成时间执行；
- `on_all_complete` 在所有计入的目标都完成后执行；
- 不等待客户端确认；
- 固定总时长模式在允许速度范围内调整打字速度，并用停留时间补齐；
- 长短不同的名字、译文和字段不能被截断。

## 8. 并发、重复与主动控制

### 8.1 通道冲突

每个内容块注册优先级与冲突策略：

- `parallel`：并行播放，主要用于 Chat；
- `queue`：等待当前内容结束；
- `replace`：中断当前内容并立即播放新内容；
- `discard`：通道忙碌时放弃本内容。

Chat 默认允许并行；Title、Subtitle、ActionBar 默认排队；紧急消息通过高优先级明确抢占。
一个演出还可以拥有整体优先级，以保持打包内容之间的关系。

### 8.2 同 ID 重复调用

每个演出可注册：

- `allow`；
- `ignore_while_active`；
- `restart`；
- `queue`；
- `refresh`；
- 调用冷却；
- 去重键所包含的目标和参数。

默认忽略同目标、同关键参数的活动中重复调用，防止 Tick 函数误刷屏。不同玩家或不同关键参数
可以成为独立实例。

### 8.3 Chat 中断结果

Chat 动画被取消或替换时只允许：

- `finalize`：补全最终文本并保留；
- `remove`：完整移除尚未完成的系统条目。

默认补全。不允许永久留下半句话，也不通过追加第二条消息补救。已正常完成的条目默认不可修改；
只有注册稳定更新键的状态行可以被后续 `refresh` 原位更新，且实现不能扫描整个聊天历史。

### 8.4 主动控制

数据包可按调用实例、演出 ID、分组标签或目标玩家执行：

- 暂停；
- 继续；
- 补全；
- 取消。

补全视为正常完成并执行完成回调；取消视为中断，只执行中断回调。每次调用具有服务端实例 ID，
数据包还可注册任务提示、紧急演出等稳定分组。

### 8.5 有限重复

内容块可以有限次数重复，并配置间隔及每次是否重新取值。重复次数受硬上限约束。V3B 不提供
无限循环的常驻文字；持续实时状态属于 V3C HUD。

## 9. 受众、权限与调用

### 9.1 受众

演出具有默认受众，每个通道和内容块可以覆盖。可用受众包括：

- 全部玩家；
- 当前主持人；
- 猎人；
- 逃走者；
- 旁观者；
- 调用时传入的合法目标玩家。

服务端最终解析身份和权限。一次调用可以让全员收到 Chat 记录、主持人收到详细 Subtitle、
猎人收到专属 ActionBar。

### 9.2 受众变化

受众计算可以选择：

- `snapshot`：调用时固定；
- `live_add`：保留原目标，并按晚加入策略加入新目标；
- `live_strict`：持续验证，失去资格时取消或补全，新符合者按策略加入。

普通短演出默认固定受众。身份秘密可以标记为敏感并强制严格验证；服务端在尚未显示的内容块
和动态字段出现前重新检查授权。

### 9.3 最小权限投影

服务端为每名玩家生成专属演出包：

- 不发送其他身份的隐藏文本；
- 不发送未命中条件分支；
- 不发送未授权参数；
- 不发送回调函数名和完整服务端定义；
- 客户端只获得自己播放所需的内容、样式、字段结果和时间线；
- 只有当前主持人预览器能请求完整诊断定义。

### 9.4 调用入口

正式 API 已提供以下能力；精确语法、权限和返回语义以 API 文档为准：

```mcfunction
# 使用注册默认受众和参数
pixel_tzz_pro message play <message_id>

# 从 Storage 读取复杂参数
pixel_tzz_pro message play <message_id> with storage <storage> <path>

# 指定合法目标
pixel_tzz_pro message play <message_id> to <targets>

# 从 Storage 读取复杂参数
pixel_tzz_pro message play <message_id> to <targets> with storage <storage> <path>
```

调用支持 `execute as` 和 `execute at` 的上下文。数据包可以把命令包装进自己的函数。命令只
接受注册 ID、合法目标和已声明参数，不能临时提交任意动态文本。

### 9.5 调用权限

- 数据包函数、服务端控制台和受信任执行源可以调用已注册演出；
- 当前主持人可以使用预览和调试命令；
- 普通玩家不能直接调用；
- 非主持人 OP 不能向他人播放或打开管理预览，必须先正式接管主持人；
- 玩家终端按钮只能通过已注册、再次验证的操作间接触发；
- 玩家手动补全只影响自己当前获准补全的演出。

### 9.6 游戏上下文

游戏阶段限制是可选能力：

- 未注册允许上下文时，演出可在任何阶段调用，默认跳过上下文检查；
- 注册了允许游戏、阶段或任务时，服务端严格验证；
- 受信任数据包函数、服务端控制台和主持人预览可以使用显式绕过；
- 客户端和普通玩家不能自行绕过；
- 已排队演出在实际开始前重新验证已声明上下文；
- 开始后默认不因阶段变化中断，除非注册严格实时策略。

### 9.7 空受众与离线目标

空受众可以配置：

- 失败且不执行回调；
- 立即视为完成；
- 无客户端地运行服务端回调时间线。

默认失败，并返回实际创建实例数量。

显式离线目标可以配置：

- 跳过；
- 整体失败；
- 在有效期内排队至上线；
- 上线后只补最终内容。

默认跳过。命令返回成功、跳过和失败数量。全体完成回调不会无期限等待离线玩家。

## 10. 屏幕、连接与恢复

### 10.1 播放前屏幕条件

每个内容块可以注册：

- 立即开始；
- 等玩家明确回到游戏画面；
- 安全关闭普通模组页面后开始；
- 不播动画，只留下最终 Chat；
- 最大等待时间与超时降级。

Chat 默认立即进入历史。Title、Subtitle、ActionBar 默认等玩家回到游戏画面。普通文字不能
擅自关闭强制流程；紧急演出必须明确声明高权限打断。每名玩家的时间线从自己的屏幕条件满足时
开始。

### 10.2 播放中被遮挡

已经开始后遇到 ESC、终端或其他 GUI，可以：

- 继续；
- 暂停；
- 补全；
- 取消。

Chat 默认继续；Title、Subtitle、ActionBar 默认暂停，回到游戏后继续。暂停具有最长时间和
超时降级。单人游戏真正暂停时，游戏时间与毫秒级表现时间都冻结。

### 10.2A 外部 HUD 文字冲突

原版或其他模组已经占用 Title、Subtitle、ActionBar 时，`external_conflict` 只决定当前客户端的
可见性、表现时钟和布局，不改变服务端标准时间线、受众、字段锁定或 callback：

- `yield`：本演出隐藏，但本地表现时钟继续；冲突结束后直接显示届时应在的帧，隐藏期间错过的
  字符音不补播。若时间线已在隐藏期间结束，则静默退休，不闪回最终帧；
- `pause`：本演出隐藏且本地表现时钟冻结；冲突结束后从隐藏前同一帧继续，隐藏期间不推进文字、
  效果或字符音，并继续遵守已注册的最长暂停与超时降级；
- `offset`：本演出继续播放，但使用通道安全偏移避开外部内容。该偏移必须从动画帧持续到正文
  停留和静态尾帧，不能在打字结束时跳回原位；外部冲突消失后才恢复注册位置；
- `overlay`：本演出继续播放并保持注册位置，不偏移、不暂停，允许与外部内容原位叠加。

四种模式都只作用于 Title、Subtitle、ActionBar 的本地投影；Chat 仍按自己的逻辑历史条目与
`chat_interrupt` 规则处理。

### 10.3 重连与晚加入

重连和晚加入分别注册：

- 从标准时间线继续；
- 从头播放；
- 只显示最终内容；
- 丢弃。

默认规则：

- 已结束演出不自动重播；
- 不重复开始音和已播放声音；
- 重要 Chat 可以配置补发最终文本；
- Title、Subtitle、ActionBar 只恢复仍在有效期内的内容；
- 晚加入者默认不接收自己在调用时不属于受众的旧演出。

连接投影终态和逻辑接收者流终态必须分层。实现中的 `connectionProjectionTerminal` 与
`connectionTerminalAction` 只属于当前物理连接，断线或建立新连接时重置；仍活动的逻辑流在
新连接上通过独立 `CREATE` 恢复，不重播已经发生的声音或回调。

### 10.4 `/reload`

每次调用固定不可变编译快照：

- 活动演出默认按调用时定义完成；
- 新调用立即使用新定义；
- 新一代删除 ID 不会让旧演出留下半句话；
- 回调函数在执行前仍需确认新一代存在且有效；
- 演出可注册完成、补全或取消的 Reload 策略；
- 默认完成旧快照，不自动按新定义重播。

### 10.5 服务器重启

每个演出可以选择：

- 临时，重启后丢弃；
- 持久化并继续；
- 持久化并补全；
- 持久化并取消。

默认临时。持久化实例必须记录字段快照、标准进度和已执行回调，保证恢复后不重复推进逻辑。
`continue` 只有在有界依赖清单仍一致时恢复；否则有合法静态降级就转成冻结最终消息，没有则
取消。冻结最终消息绑定冷启动批准它的 definition generation；若玩家加入前发生成功 Reload，
旧审批立即 fail-closed。由依赖变化降级的含参数实例不要求旧依赖在加入时重新一致，但必须重新
通过当前上下文、受众、节点、参数和整份静态降级覆盖校验。

终态控制的持久化要求不对称：无文本 `CANCEL` 的 checkpoint 是 best-effort，失败仍须完成当前
连接清理；`FINALIZE` 必须先成功 checkpoint 最终字段，失败时改发无文本 `CANCEL`，不能留下
未持久化的最终值或孤立旧投影。

### 10.6 传送、维度与重生

演出可以绑定玩家或世界：

- 玩家绑定文字跟随玩家跨传送和维度继续；
- 世界绑定演出离开冻结调用原点所在维度后按 `dimension_exit` 配置处理；区域或距离退出不属于 V3B；
- 屏幕声音可以跟随玩家；
- 世界位置声音保留固定坐标；
- 原版重生可配置继续、补全或取消；
- 默认屏幕文字绑定玩家，未来 V3E 可通过专门策略接管。

普通网络实例的重生与维度生命周期继续由服务端裁决。只有本地内建演出，或服务端已用 `FINISH`
关闭权威流并锁定全部最终字段的实例，才由客户端接管剩余表现生命周期；接管时只消费已授权、已
归一化的投影，不再读取数据包条件、字段或回调。原版重生包中的保留数据标志用于区分真实重生与
纯维度切换，玩家绑定的 `dimension_exit` 在投影阶段固定归一为继续。

## 11. 服务端回调

演出可以注册：

- 开始回调；
- 指定时间或关键帧回调；
- 每名目标的完成回调；
- 全部目标完成回调；
- 中断回调。

回调以服务端标准时间线执行，绝不等待客户端报告。玩家减少动态、手动补全、掉线或低 FPS
不能改变权威回调时机。自然权威完成也不得吞掉客户端已经获准但仍在 Subtitle、Title 或
ActionBar 通道中排队的表现：服务端先锁定最终字段并关闭权威流，客户端再独立排空这些动画；
主动补全、取消和撤权安全终止仍按各自即时语义执行。客户端排空期间的重生或离开冻结维度只影响
尚未显示完的本地表现，不撤销、重复或延迟已经按服务端标准时间线提交的 callback。

每个回调明确执行上下文：

- 以服务端执行；
- 以最初调用者执行；
- 分别以目标玩家执行；
- 在调用原点或目标当前位置执行。

回调可以从只读临时 Storage 获取演出 ID、实例 ID、目标 UUID、锁定参数、状态和中断原因。
只有数据包注册的函数可以成为回调。失败只记录一次，默认不自动重试，防止重复世界修改。

## 12. 历史、任务与现有系统联动

### 12.1 玩家历史与赛后回顾

历史联动完全可选：

- 默认播放文字但不创建历史；
- 数据包可注册历史标题、正文、所属任务、时间点和受众；
- 回顾保存字段当时锁定的最终值；
- 回顾内容可以与屏幕短提示不同；
- 回顾默认显示静态最终内容，不自动重播动画；
- 只有数据包明确允许时才提供重播。

3B 不把主持人伪装成普通玩家终端，也不扩展 2D 主持人任务时间线载荷来承载消息正文和重播
授权。因此 `history.audience` 当前不得包含 `current_host` 选择器；编译器会明确拒绝该不可达
配置。cue 的实时播放受众仍可使用 `current_host`，玩家历史则必须投影给拥有玩家终端历史入口
的实际查看者。

### 12.2 任务与流程事件

现有任务、阶段和强制流程可以可选引用演出 ID，包括：

- 任务开始、节点、完成、中断；
- 游戏开始、暂停、继续、结束；
- 初始化、身份变化、准备完成；
- 强制流程开始、个人完成、全员完成；
- 后续捕获、释放和复活事件。

框架自动提供经过注册的任务、玩家、结果和时间参数。复杂逻辑仍由函数自行调用。缺少引用时
不显示任何模组擅自生成的正式文案。

### 12.3 现有文字提示迁移

现有模组自有 Subtitle 打字、成功提示和任务开始/结束提示必须迁移到 V3B 调度器：

- 已验收视觉和时序先保持；
- 模组必要系统提示使用内置 ID；
- 游戏文案由数据包注册；
- 旧代码不再维护第二套字符、声音或队列状态；
- 普通原版文字仍不进入 V3B。

## 13. 资源、预加载与兼容

### 13.1 预加载

客户端连接或 Reload 后可以静默预加载：

- 通用动画预设；
- 光标样式；
- 声音引用；
- 非敏感渲染资源。

具体正文、身份分支、秘密参数和回调信息不能提前下发。调用时只发送该玩家的最小演出包。
播放前不出现等待页面、红字或临时占位。`final_only` 的 capability/asset 握手最多等待 100 个
游戏 Tick（20 TPS 下约 5 秒），且截止点不能滑动；超时后仅在整份静态降级仍完整授权时显示
最终文本，没有授权文本则静默结算。
定期同步不能造成界面或同步标记闪烁。

### 13.2 客户端资源缺失

- 字体、声音和特殊效果可以注册回退资源；
- 字体缺失时使用默认字体并安全重排；
- 字符音缺失时静默跳过或使用默认声音；
- 普通玩家不弹红色错误窗口；
- 关键资源可以标记为开局准备所需；
- 非关键资源只写入诊断；
- 客户端资源包 Reload 时按注册策略完成、补全或取消，不在中途替换字体。

### 13.3 原版与其他模组内容

V3B 只管理自身演出，不拦截或清除外部 Title、Subtitle、ActionBar。检测到外部内容时可：

- 让出；
- 暂停；
- 移动到安全偏移；
- 明确叠加。

默认让出。取消 V3B 内容不能清除外部内容。

### 13.4 聊天模组

动态 Chat 必须检测原位更新能力：

- 兼容时正常播放；
- 无法安全更新时只插入一次最终静态文本；
- 不通过逐帧新增消息伪造动画；
- 只降级 Chat 通道，其他通道继续；
- 诊断工具记录原因，普通玩家不弹错；
- Chat Heads 等只装饰条目、保留原版消息身份的模组应保持兼容并进入实机矩阵。

## 14. 辅助功能与玩家偏好

V3B 已接入本地偏好存储、简洁设置 UI、原版按键设置入口和播放端纯表现应用；手动补全按键
默认未绑定，完整 Minecraft 实机验收仍未完成：

- 动画速度倍率；
- 减少动态效果；
- 字符音开关与独立音量；
- 光标闪烁开关；
- 高对比度光标和新字颜色；
- 手动补全设置。

数据包提供推荐效果，玩家可以让效果更安静、更快或更易读，但不能隐藏最终内容，也不能拖延
服务端流程。

“跳过内容”和“补全动画”必须区分：

- 最终内容永远不能被跳过；
- 单条演出声明是否允许玩家手动补全；
- 允许时只让动画瞬间完成；
- 减少动态属于辅助降级，不算跳过；
- 手动补全按键可在原版按键设置中绑定，默认不占用任何键；
- 数据包不能为玩家强占键位；
- 未绑定时不显示按键提示。

完整统一辅助页面仍可在 V3F 收口，但 V3B 实现不能留下无法兼容的动画架构。

## 15. 预览、诊断与错误隔离

### 15.1 主持人预览器

管理员工具增加动态消息预览入口：

- 搜索注册 ID；
- 查看通道、时间线、参数、受众、回调和警告；
- 填入测试参数；
- 默认只对主持人自己预览；
- 向其他玩家播放需要选目标和二次确认；
- 可以暂停、补全、取消；
- 默认不执行正式回调、不写历史、不改变游戏；
- 可以显式开启单项测试。

3B-6 已接入适合数据包开发的列表、检查、预览和控制命令；其 Minecraft 内回显、分页、
无副作用边界和多人权限仍须按验收清单逐项确认。

### 15.2 注册错误

- 普通无效 ID 单独禁用，其他合法资源继续；
- 关键演出可以标记为 `required`，无效时阻止游戏进入可开始状态；
- 无效调用只向命令源和日志报错；
- 普通玩家不弹错、不闪红色页面；
- 注册静态降级内容时可以直接使用降级；
- 诊断必须指出数据包、资源 ID、文件和字段路径。

## 16. 性能与安全上限

V3B 使用模组不可突破的硬上限和数据包可调的更低软上限，覆盖：

- 单条可见字符；
- 行数；
- 内容块；
- 总时长；
- 同时活动实例；
- 队列；
- 声音节点；
- 回调节点；
- 条件与变体复杂度；
- 持久化实例；
- 待上线实例。

超限时优先使用已注册的最终静态内容或明确失败，不能静默截断正文或丢失回调。当前已经冻结的
硬数值、线格式边界和软限制范围见
[`DATA-PACK-MESSAGE-API-3B.md`](DATA-PACK-MESSAGE-API-3B.md#15-硬上限)；长中文、Emoji、
多语言、多字段、多通道和多客户端压力测试仍必须验证这些边界在 Minecraft 内的实际表现。

实现必须满足：

- 不每 Tick 扫描完整聊天历史；
- 不把隐藏受众内容发送到客户端；
- 不因客户端确认延迟服务端状态；
- 不允许回调、重连或重启导致重复推进；
- 不允许无限循环；
- 不允许单个高延迟或离线目标无限阻塞全体；
- 不允许资源错误把普通玩家困在错误界面。

## 17. 默认值总表

未显式注册时采用以下默认行为：

| 项目 | 默认 |
|---|---|
| 游戏阶段限制 | 不检查，可在任意阶段调用 |
| 同 ID 活动中重复调用 | 忽略同目标、同关键参数重复 |
| Chat 冲突 | 并行 |
| Title / Subtitle / ActionBar 冲突 | 排队 |
| Chat 被中断 | 补全最终文本 |
| 屏幕开始条件 | Chat 立即；其他通道等待游戏画面 |
| 播放中被界面遮挡 | Chat 继续；其他通道暂停 |
| 受众 | 调用时快照 |
| 离线目标 | 跳过 |
| 空受众 | 调用失败且不执行回调 |
| Reload | 活动快照完成，新调用使用新定义 |
| 服务器重启 | 不恢复临时演出 |
| `final_only` 新连接握手 | 最多 100 游戏 Tick；超时只尝试完整授权的静态降级 |
| 发言者 | 关闭，使用系统演出 |
| 手动补全按键 | 未绑定 |
| 历史记录 | 不自动写入 |
| 外部文字冲突 | 让出 |
| 缺少 Chat 原位更新能力 | 一次性显示最终文本 |
| 无限循环 | 不允许 |

## 18. 实施架构

V3B 实现必须复用现有边界：

- `DefinitionCompiler`、`DefinitionRegistry` 和 generation 原子发布负责资源编译；
- `BindingRuntime`、`BindingContext` 和 V3A 可信投影负责字段与条件；
- 服务端运行时负责授权、参数、受众、实例、时钟、回调和恢复；
- 客户端只负责已授权演出包的渲染、声音和本地辅助设置；
- Chat 更新、Title 系通道和 ActionBar 共享一套客户端时间线，不各建调度器；
- 持久化继续通过世界状态迁移，不创建旁路存档；
- 任务事件继续使用 2D/V3A 权威事实和冻结定义，不创建第二套任务事实。

建议实施顺序：

### 18.1 3B-1：资源与编译

- 新资源类型和格式版本；
- 动画预设；
- 文本组件、参数、动态字段和条件；
- 引用、覆盖、复杂度和资产校验；
- 候选 generation 原子发布；
- 编译器与压力夹具自检。

### 18.2 3B-2：服务端权威实例

- 受控调用与权限；
- 参数解析；
- 受众与上下文；
- 标准时间线；
- 并发、去重、冷却和控制；
- 回调账本；
- 最小权限投影。

### 18.3 3B-3：动态 Chat

- 原版历史逻辑条目；
- 原位帧更新；
- 普通聊天共存；
- 交互组件；
- Chat 设置、容量和聊天模组降级；
- Unicode、换行和预排版。

### 18.4 3B-4：统一文字与声音

- Title、Subtitle、ActionBar；
- 动画原语；
- 光标、新字颜色和回色；
- 多通道同步；
- 声音时间轨；
- 外部内容让出与避让。

### 18.5 3B-5：生命周期与恢复

- 屏幕条件；
- 暂停和遮挡；
- 重连与晚加入；
- Reload 快照；
- 可选持久化；
- 维度、传送和重生；
- 低 FPS、低 TPS 与资源 Reload。

### 18.6 3B-6：集成与工具

- 任务、阶段和流程挂钩；
- 历史联动；
- 现有 Subtitle 调度迁移；
- 玩家偏好；
- 主持人预览与诊断；
- 示例基础数据包和压力数据包。

### 18.7 3B-7：收口

- 正式数据包 API 文档；
- Schema 与命令示例；
- 自动测试；
- 独立服务端回归；
- 多客户端逐项实机验收；
- 兼容矩阵与性能结论；
- 用户明确确认后再提交、推送和合并。

## 19. 验证计划

### 19.1 自动检查

至少覆盖：

- 合法与非法资源；
- 数据包同 ID 覆盖；
- 动画预设引用；
- 原版富文本和交互事件；
- Score、NBT/Data、Selector 和绑定字段；
- 三种动态字段取值模式；
- 演出级与局部字段；
- Unicode 字素、Emoji、多行与溢出；
- 动画组合与硬上限；
- 冲突、优先级、重复、刷新和控制；
- 受众、敏感内容和最小投影；
- 空受众、离线、上下文和权限；
- 多人标准时间线；
- 回调一次性账本；
- Reload、重连、持久化和迁移；
- 外部资源缺失和静态降级；
- 现有 V3A、2D、2C 协议与状态回归。

### 19.2 实机验收

沿用逐项反馈节奏，至少验证：

- 五客户端多身份受众；
- Chat 条目原位动画、历史保留和玩家聊天顶起；
- Title、Subtitle、ActionBar 同步与排队；
- 光标、新字颜色、瞬切和渐变回色；
- 动态字段三个取值时机；
- 长中文、Emoji、多语言和超长玩家名；
- 同步声音只播放一次；
- ESC、终端、强制流程和页面关闭时序；
- 暂停、继续、补全、取消和抢占；
- 掉线、重连、晚加入、Reload 和服务器恢复；
- 不同窗口、GUI Scale、低 FPS 和模拟延迟；
- Chat Heads 以及至少一种改变聊天界面的兼容场景；
- 预览器默认不执行正式回调或写历史；
- 资源缺失时普通玩家无红字、无错误页面、无闪烁。

自动检查不能替代 Minecraft 实机画面、声音和多人同步验收。

## 20. V3B 完成定义

V3B 只有同时满足以下条件才算完成：

1. 一个稳定 ID 能可靠打包并调用多个文字通道；
2. 数据包可以复用预设并逐内容覆盖；
3. 原版富文本和可信动态字段按三种时机正确锁定；
4. Chat 真正进入历史且不破坏正常玩家聊天；
5. Title、Subtitle、ActionBar 与 Chat 使用统一时间线；
6. 动画、声音、排版和辅助降级达到 V3 统一质量基线；
7. 服务端权威处理受众、参数、上下文、条件和回调；
8. 并发、重复、取消、补全和优先级语义完整；
9. 掉线、重连、Reload、重启和资源异常不会重复回调或破坏状态；
10. 客户端只收到获准内容，无法提交任意文本、目标或函数；
11. 现有模组自有文字提示迁移到统一调度器；
12. 主持人预览、诊断、玩家偏好和数据包示例可用；
13. 硬上限由压力测试确定并有静态降级；
14. 完整自动检查、独服回归和用户逐项多客户端实机验收全部通过；
15. 文档、实现、示例和实际运行行为一致；
16. 用户明确确认 V3B 收口。

在以上条件满足前，不得把 V3B 标记为完成，也不能提前把 V3C HUD、V3D 运镜或 V3E 捕获
内容混入本阶段。
