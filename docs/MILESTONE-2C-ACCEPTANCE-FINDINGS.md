# Pixel-Tzz-Pro 里程碑 2C 实机验收问题总表

状态：集中修复已实现，并通过自动检查与用户分项实机复验
整理日期：2026-07-28
适用范围：2C 主持人控制台、目标选择、二次确认、强制流程、流程遥测、数据包示例页面及相关服务端权威逻辑

## 1. 本文目的

本轮反馈最初按截图和测试顺序记录，同一个共享问题可能出现在多个页面。集中修复时不得只修改用户截图中的页面；必须修复共享状态、组件或权威计算，并回归所有调用方。

本文将原始 28 条反馈归并为 13 个共享修复域，并明确：

- 共享根因；
- 所有已知受影响界面；
- 应当一次修复的位置；
- 统一验收标准；
- 原始问题的完整映射。

本文不替代原始截图和日志证据。下文“当前问题”保留的是集中修复前的原始症状，实际实现状态以第 9 节为准。

## 2. 修复原则

1. 玩家身份、头像、搜索框、名单、按钮、确认后果和状态徽标必须复用共享组件，不为单个页面复制实现。
2. 候选资格、排除原因、流程完成状态和初始化状态由服务端权威计算；客户端只负责展示，不重新推导业务规则。
3. 目标预览、二次确认和最终提交必须使用同一套资格语义，并在最终提交时再次校验。
4. 数据包声明业务内容和筛选条件；模组提供通用能力，不硬编码本示例数据包的角色、流程或节点 ID。
5. 页面重建、倒计时更新和实时快照更新不得重置 hover、焦点、滚动、选择或动画状态。
6. 成功反馈、失败反馈、等待反馈和阻塞诊断必须分层，不使用一个通用整屏结果页处理所有情况。
7. 集中修复完成后统一构建；是否通过仍以用户实机复验为准。

## 4. 共享修复域

### A. 玩家身份与头像组件

#### 当前问题

- 多个页面只显示玩家名，没有头像、身份或在线状态。
- 部分页面使用默认头像或只渲染基础脸部，没有帽子/头饰外层。
- 离线玩家缺少真实皮肤缓存的黑白表现。
- 数据包页面无法复用与模组控制台相同的玩家身份条。
- 发起人、目标玩家、未完成人员分别使用不同展示方式。

#### 一次修复要求

建立一个共享玩家身份表现模型和渲染组件，至少支持：

- 稳定 UUID；
- 玩家名；
- 当前身份及身份色；
- 在线/离线；
- 初始化状态；
- 当前流程状态；
- 可选/不可选及原因；
- 真实皮肤头部基础层；
- 帽子/头饰外层；
- 离线时最后缓存头像的黑白和降亮度表现；
- 加载中或无法取得皮肤时的中性未知占位符。

数据包页面通过通用节点或绑定上下文使用该组件；不得在每个 JSON 页面重新拼头像、名称和状态。

#### 必须回归

- 目标选择行；
- 二次确认影响对象名单；
- 当前强制流程未完成/已完成名单；
- “由某玩家发起”身份条；
- 数据包通用初始化确认页；
- 猎人说明页中的玩家列表；
- 离线、重连和皮肤迟到加载；
- Compact、Standard、Wide。

### B. 名单、搜索与资格说明

#### 当前问题

- 目标页完成度低于既有 2B 玩家列表。
- 搜索框退化为原版黑框。
- 不可用玩家与可用玩家混排，主持人甚至出现在业务候选名单。
- “选择可用玩家”是高风险全选，与多数业务不符。
- 容量 `64` 被错误表现为当前可选人数。
- 初始化状态和不可选原因没有显示。

#### 一次修复要求

所有目标选择页面复用同一名单和搜索组件：

- 主题化搜索框、搜索图标、焦点反馈和清除入口；
- 真实可选人数、已选人数和最小选择数；
- 稳定 UUID 驱动的选择态；
- 有界虚拟滚动；
- 明确初始化状态徽标；
- 不可选原因使用中文业务说明；
- 可用对象优先，不可用对象默认不进入主名单；
- 如确需解释排除对象，放入折叠的“已排除”区域；
- 默认不提供全选，只有数据包操作显式声明允许且风险合理时才出现。

无活动流程时，“未在流程中”可以降级；身份、在线和初始化状态优先。

#### 必须回归

- 指定为猎人；
- 重新初始化猎人；
- 设为旁观者；
- 恢复为逃走者；
- 初始化并恢复为逃走者；
- 补充流程成员；
- 移除流程成员；
- 转交主持人；
- 0、1、32、64 人；
- 搜索、滚动、选择后滚出再滚回。

### C. 权威候选集合

#### 当前问题

- 目标页展示的玩家与服务端最终实际执行集合不一致。
- 已完成 `if_incomplete` 的玩家仍进入确认页，最终又被服务端跳过。
- 无实际目标时仍生成确认或进入空路由页。
- 主持人、已有猎人、旁观者等不合格对象只在客户端置灰。
- 补员把容量满和冻结定义失败合并成一个原因。

#### 一次修复要求

服务端提供唯一的候选资格投影，供以下阶段共同使用：

1. 操作目录可用性；
2. 目标快照；
3. 二次确认影响对象；
4. 最终提交复核；
5. 活动流程名单调整。

投影结果至少包含：

- 可执行目标；
- 排除对象；
- 每个排除对象的稳定原因代码和中文说明；
- 真实最小/最大数量；
- 当前容量；
- 相关初始化或完成状态；
- 生成时的 state revision 和 definition generation。

最终提交仍需重新计算；目标变为零时返回明确无操作结果，不创建空流程。

#### 必须回归

- 已完成通用初始化后再次发起；
- 主持人排除；
- 已有猎人与非猎人分流；
- 未初始化玩家设为旁观者；
- 旁观者恢复参与；
- 确认期间玩家掉线、身份变化或流程变化；
- 容量满、状态不允许、冻结定义损坏分别返回不同原因。

### D. 二次确认生命周期

#### 当前问题

- 第一次点击操作先闪过等待页，再进入二次确认。
- 后果区域固定过高。
- 每秒倒计时重建按钮并重播 hover 动画。
- 目标只用一行文本展示。
- 令牌过期只能退出重走流程。
- `/reload` 后旧确认仍显示为有效，直到提交才暴露失效。

#### 一次修复要求

- 审阅请求期间短时间不显示状态；超过阈值才显示中性“正在审阅”。
- 收到确认后直接进入确认页，不先展示结果或错误式等待。
- 确认页高度按后果和目标数量自适应，并设置最大高度。
- 目标名单使用共享玩家身份组件。
- 不向用户显示确认令牌倒计时；二次确认内容保持稳定，不按秒重建按钮。
- hover 动画只在鼠标进入边界时触发。
- 仅令牌自然过期时，同一次“确认执行”自动重新审阅、取得新令牌并继续提交，不能要求第二次点击。
- reload、revision、目标或操作后果变化后立即禁用旧确认，并要求人工重新审阅变化后的内容。
- 最终提交继续使用单次令牌、防重放和上下文复核。

#### 必须回归

所有带二次确认的操作，而不只是猎人操作：

- 认领/接管/转交主持人；
- 通用初始化；
- 指定和重新初始化猎人；
- 设为旁观者及恢复参与；
- 补员、移除、取消；
- 回调重试；
- 未来数据包注册的高风险操作。

### E. 操作反馈与等待状态

#### 当前问题

- 正常短网络往返会闪红字。
- 成功操作占用独立全屏结果页。
- 无目标路径没有明确结果。
- reload 作废确认后客户端没有立即解释。

#### 统一状态模型

| 状态 | 表现 |
| --- | --- |
| 短等待 | 不显示 |
| 超过等待阈值 | 中性“处理中/正在审阅”，不使用红色 |
| 成功且无需人工处理 | 关闭控制界面，回到游戏，subtitle 打字动画和一次音效 |
| 无符合目标 | 原位清楚说明，不创建流程，不使用故障红色 |
| 仅令牌自然过期 | 保持当前页面，同一次点击自动重新审阅并继续提交 |
| 上下文或后果变化 | 原位说明原因并要求人工重新审阅 |
| 失败或阻塞 | 保留有界详情和恢复操作 |
| 超时 | 明确错误和安全返回路径 |

成功反馈适用于所有管理员操作，不为“认领主持人”和“初始化”分别实现。

### F. 控制台上下文与目录

#### 当前问题

- 主页大块 `NEXT` 只显示同步状态，浪费空间。
- “全部操作”入口不明显。
- 静态排序把不可用操作放在顶部。
- 控制台没有根据活动流程和当前阶段把最可能的动作放到主页。

#### 一次修复要求

- 同步状态改为右上角紧凑徽标：已同步、同步中、未同步。
- 主页显示当前上下文最相关的 2–4 项快捷操作。
- 活动流程期间优先显示流程进度、未完成人员和名单管理。
- 待机时优先显示初始化、身份准备和阶段操作。
- 完整目录入口持续可见，但视觉权重低于主要操作。
- 排序为：相关且可用、其他可用、不可用。
- 排序只在打开、显式刷新或一次操作终态后更新，避免鼠标下按钮跳位。
- 数据包声明基础优先级和适用上下文，模组统一排序。

### G. 导航与临时状态

#### 当前问题

- 从确认页返回后，第一次重新进入猎人操作卡在空路由页。
- “返回”和“取消”语义混合。
- 倒计时、刷新或页面重建可能泄漏 pending flag、目标快照或草稿。

#### 一次修复要求

- 返回：回到上一层并保留可继续编辑的目标草稿。
- 取消：清除草稿、pending 请求、目标快照和本地确认，并通知服务端作废令牌。
- 完成：清理整个导航事务。
- reload、断线和世界切换：作废事务并显示准确状态。
- 同一操作重新进入时必须发起新的权威请求。
- 导航状态机按 operation ID 和 request sequence 隔离，不能由页面实例重建隐式控制。

#### 必须回归

每种目标操作都执行：

1. 目标页返回再进入；
2. 确认页返回再进入；
3. 确认页取消再进入；
4. 倒计时期间返回；
5. reload 后返回；
6. 连续进入两个不同操作。

### H. 强制流程容器与实时状态

#### 当前问题

- 强制页面铺满全屏。
- 状态说明占据一整行，正文空间利用差。
- Esc 被完全拦截，玩家无法设置或正常断开连接。
- 主持人流程页不会随成员推进自动刷新。
- 重连恢复页面时仍播放普通加载成功音效。

#### 一次修复要求

- 强制页面使用居中有界面板，外围保留压暗游戏画面。
- 面板外点击和普通 Esc 不能绕过强制流程。
- Esc 打开受限暂停菜单，允许设置、无障碍和断开连接。
- “强制/服务端推进/完成解除”等说明压缩为辅助徽标。
- 服务端主动向当前主持人推送成员节点、完成、在线和名单变化。
- 客户端按 UUID 原位更新，保留滚动、焦点和 hover。
- 高频变化合并限频。
- 恢复强制页面时取消普通加载成功文字和打字音。
- 精确屏蔽已完成模组握手会话中的原版“服务器消息无法验证”Toast，不影响其他安全提示。

### I. BossBar 与完成动画

#### 当前问题

- 完成到达 `1/1` 后立即消失。
- 主持人页面和 BossBar 状态不同步。
- 补员功能当前被冻结快照恢复问题阻塞。

#### 一次修复要求

- 服务端仍立即提交终态。
- 客户端先显示约一秒“已完成”，播放一次完成音。
- 随后约半秒渐隐，不逐帧发送网络包。
- 新流程替换旧完成动画。
- 断线和切换世界立即清理。
- 补员、移除、掉线和重连更新完成数、总数和分类。
- 只有当前主持人看到 BossBar。

### J. 文案、中文化和信息层级

#### 当前问题

- 玩家可见页面出现“夹具、2C 验收、always”等开发术语。
- 节点显示内部 ID `briefing`。
- 英文枚举抢占中文主信息。
- 不可选、快照失败和令牌失效原因不准确或被合并。

#### 一次修复要求

- 中文为主信息；英文只作更小、更暗的辅助设计文字。
- 数据包流程节点可声明显示名。
- 缺省节点名回退到冻结页面标题。
- 原始 ID 和枚举只出现在开发诊断。
- completion policy、角色、节点、状态和拒绝原因均本地化。
- 面向玩家的示例文案不得出现实现和验收术语。
- 不同失败原因不得合并成模糊句子。

### K. 冻结快照和身份业务

#### K1. 补员冻结快照

`ExecutionSnapshotCompiler.freezeSupportingDefinitions(...)` 已保存来源 panel action，但 `restore(...)` 显式过滤 `PANEL_ACTION`，导致恢复后的定义缺少 `sourceActionId`，活动流程补员恒被禁用。

修复必须位于共享冻结恢复路径，并增加真实 `freeze -> restore -> activeFlowDefinitions -> 补员可用` 回归检查；不得在补员按钮处绕过。

#### K2. 猎人操作拆分

- “指定为猎人”只列非猎人。
- “重新初始化猎人”只列当前猎人。
- 两者使用独立数据包操作和候选规则。

#### K3. 旁观者

- 未初始化玩家可以直接被设为旁观者。
- 删除 `set_spectator` 的 `completed_flows` 前置条件。
- 主持人、已有旁观者和其他不合格对象由服务端排除。
- 转换为旁观者使用二次确认后 `immediate` 生效，不打开强制页面。

#### K4. 恢复参与

当前没有目标身份为逃走者的反向操作。使用现有 `assign_role` 能力，由数据包补充：

1. “恢复为逃走者”：已满足初始化要求的猎人或旁观者，确认后立即生效。
2. “初始化并恢复为逃走者”：未满足要求的猎人或旁观者先完成数据包流程，完成后提交逃走者身份。

不引入隐式“恢复上一个身份”栈。恢复猎人走独立猎人操作，保证后果明确。

### L. 按钮、悬停与页面转场

#### 当前问题

- 新增 2C 页面存在按钮风格和悬停反馈退化，只在部分返回按钮上保留既定动画语言。
- 倒计时刷新会重播 hover 动画。
- 某些页面返回后导航状态异常，视觉转场与事务状态没有保持一致。
- 原始问题曾在猎人目标页被指出，但同一风险存在于所有新 2C 内置页面。

#### 一次修复要求

- 所有内置页面复用现有 `ConsoleButton`，不得直接回退到原版灰按钮。
