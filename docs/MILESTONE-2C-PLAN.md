## 1. 里程碑目标

2C 要证明：数据包注册的极短强制流程可以由服务端模组真实、安全、持久地执行，而不是继续停留在 2B 的本地预览和请求信封。

完整验收闭环为：

1. OP 通过图形化界面认领主持人；
2. 主持人打开上下文控制台；
3. 控制台显示当前阶段真正可执行的数据包操作；
4. 主持人选择目标、阅读后果并完成二次确认；
5. 服务端锁定名单并创建唯一活动强制流程实例；
6. 目标玩家进入不能自行关闭的短流程；
7. 玩家每次提交都由服务端验证并保存节点进度；
8. 掉线、重连和正常服务器重启后继续上次节点；
9. 主持人通过 BossBar、控制台和名单查看完成进度；
10. 所有人完成后，流程实例结束，但阶段不会自动推进；
11. 猎人初始化完成后，待身份变更原子生效；
12. 回调、审计、重复请求、资源异常和 `/reload` 均有明确结果。

2C 不决定正式教程、剧情、地图、任务或开局节奏。正式开局前流程在模组框架完成后由数据包另行编写。

## 2. 已确认的产品决策

### 2.1 全局单强制流程

- 同一活动游戏同时最多存在一个未结束的强制流程实例；
- 当前实例结束或取消前，不能发起另一个强制流程；
- 同一阶段可以顺序发起多个流程，例如分批初始化猎人后再发起通用初始化；
- 存在未结束强制流程时，阶段推进请求必须失败；
- 全员完成只满足推进条件，不自动转换阶段；
- 2C 不建设玩家级强制流程队列，也不显示“排队第 N 位”。

### 2.2 流程完成策略

2C 为发起流程的操作增加可选 `completion_policy`：

| 值 | 语义 |
|---|---|
| `if_incomplete` | 已完成当前流程 ID 与版本的玩家直接计为完成，不重复打开 |
| `always` | 即使有历史完成记录，也创建本次执行并要求重新完成 |
| `resume_only` | 只恢复匹配的未结束实例，不创建新实例 |

默认与当前验收内容：

- 普通 `start_flow` 默认 `if_incomplete`；
- 通用初始化验收夹具显式使用 `if_incomplete`；
- `assign_role` 绑定身份初始化流程时默认 `always`；
- 猎人初始化验收夹具显式使用 `always`；
- 相同来源操作、流程和目标已处于当前实例时，重复请求拒绝，不叠加执行。

该字段是对 API v1 的向后兼容可选扩展，不提高现有定义的 `format_version` 或 `api_version`。

### 2.3 正式内容边界

- 现有组件展示、按钮展示、响应式页面和压力页面继续仅用于预览；
- 新建独立、明确标注为 2C 验收夹具的短流程；
- 通用夹具只包含“简短说明 → 最终确认 → 完成”；
- 猎人夹具只包含“身份调整说明 → 最终确认 → 完成”；
- 夹具页面遵循当前 2B UI 质量标准，但不冒充正式教程；
- 正式数据包以后替换流程和页面，不修改模组执行器；
- 2C 不把验收夹具安装到未来正式游玩世界。

## 4. 权威边界与核心不变量

### 4.1 唯一权威

- 服务端模组是主持人、活动游戏、阶段、玩家记录、流程实例、节点进度、完成记录和待身份变更的唯一权威；
- 客户端只显示服务端快照并提交有类型意图；
- 数据包只能通过已编译定义、受检回调和受控操作影响流程；
- 记分板、队伍和标签不得复制第二套流程状态；
- 所有状态变更只在服务端主线程提交；
- 客户端动画完成与否不影响服务端流程结果。

### 4.2 必须始终成立

1. 每个世界最多一名主持人；
2. 每个活动游戏最多一个未结束强制流程实例；
3. 每个参与者在实例内最多一个当前节点；
4. 每个实例使用一份不可变执行快照；
5. 每个高风险确认令牌最多成功消费一次；
6. 每个参与者在一个实例内最多自然完成一次；
7. `on_start`、`on_player_complete` 和 `on_all_complete` 各自遵守最多一次语义；
8. 待身份变更只在绑定玩家自然完成指定实例后提交；
9. 移除或取消不会伪造完成记录；
10. `/reload` 不清除主持人、玩家记录、实例、进度、完成记录或待变更；
11. 未通过当前状态 revision 校验的请求不能部分执行；
12. 定义、资源或持久化异常时失败关闭，不猜测安全结果。

## 6. 世界状态 Schema v2

### 6.1 顶层结构

Schema v2 至少持久化：

```text
schema_version
state_revision
active_game_id
active_phase_id
host
players
active_forced_flow
completion_history
audit
recovery_snapshot_metadata
```

未结束流程的完整执行快照作为 `active_forced_flow` 的一部分保存。一次性确认令牌不持久化。

### 6.2 主持人记录

主持人记录包含：

- UUID；
- 最近名称；
- 认领或获得权限的时间；
- 最近操作者；
- 最近操作类型：认领、转交或接管。

主持人权限不改变原版 OP 状态。

### 6.3 玩家记录

玩家记录以 UUID 为键，至少包含：

- 最近使用的名称；
- 正式身份 ID；
- 可选队伍 ID；
- 正式生存状态 ID；
- 玩家持久字段值及字段版本；
- 当前待身份变更；
- 当前活动流程参与状态；
- 完成历史摘要；
- 首次和最近出现时间；
- 在线快照只作派生数据，不作为离线真值。

玩家第一次进入当前活动游戏且没有记录时，使用游戏定义的 `default_role` 和 `default_life_state`。数据包显示名不能参与默认值判断。

### 6.4 强制流程实例

活动实例至少包含：

- 随机 UUID 实例 ID；
- 游戏 ID；
- 流程 ID 与流程版本；
- 来源面板操作 ID；
- 发起主持人 UUID；
- 创建时间；
- 创建时阶段 ID；
- 创建时 definition generation；
- 完成策略；
- 实例状态；
- 锁定成员；
- 每成员进度；
- 完整数、总数和 revision；
- 执行快照；
- 已调用回调标记；
- 阻塞诊断；
- 最近更新时间。

实例状态：

```text
active
completed
canceled
blocked
```

`blocked` 不等于取消。它保留原始状态并阻止不安全推进。

### 6.5 成员进度

成员记录至少包含：

- UUID 和锁定时名称；
- 当前节点 ID；
- 状态；
- 流程作用域字段；
- 页面实例 ID；
- 客户端请求序号窗口；
- 最后成功提交时间；
- 离线标记及最近在线时间；
- 完成时间；
- 移除操作者、时间和原因。

成员状态：

```text
not_started
in_progress
offline
already_complete
completed
removed
blocked
```

离线只改变展示状态，不改变分母或节点进度。

### 6.6 待身份变更

待身份变更记录包含：

- 目标玩家 UUID；
- 目标身份 ID；
- 来源操作 ID；
- 绑定流程实例 ID；
- 创建操作者和时间；
- 创建时正式身份；
- 创建时状态 revision；
- 当前状态。

状态：

```text
pending
applied
canceled
blocked
```

正式身份在流程完成前不变化，TAB 也不提前显示目标身份。

### 6.7 完成历史

完成记录至少按以下键判定：

```text
player UUID + flow ID + flow version
```

每次自然完成记录：

- 实例 ID；
- 完成时间；
- 来源操作；
- 是否为强制重做；
- 完成时 generation。

旧版本记录保留，但不满足新版本的 `if_incomplete`。

### 6.8 审计

2C 审计以下事件：

- 主持人认领、转交、接管；
- 确认令牌签发、取消、过期、拒绝和消费；
- 流程创建、阻塞、完成和取消；
- 成员补充、移除、自然完成；
- 待身份变更创建、提交、取消和阻塞；
- 回调失败和人工重试；
- Schema 迁移和恢复；
- 权限或 revision 拒绝。

普通页面浏览、悬停和动画帧不进入审计。内存和存档中的审计明细必须有界；超出明细上限时保留准确计数和最近事件，不阻断核心流程。

## 7. Schema v1 → v2 迁移

### 7.1 迁移触发

- 仅在加载使用 2C 模组的世界时执行；
- 普通 `/reload` 不执行 Schema 迁移；
- 迁移前保存原始恢复快照；
- 候选数据和当前定义全部验证后才提交新 Schema；
- 失败时继续保留原始数据并进入只读诊断状态。

### 7.2 无歧义自动迁移

满足以下全部条件时自动迁移：

1. 旧 Schema 为 v1；
2. 旧阶段为 `IDLE`；
3. 当前恰好有一个健康游戏定义；
4. 该游戏的初始阶段、默认身份和默认生存状态均有效。

结果：

- `active_game_id` 使用唯一健康游戏；
- `active_phase_id` 使用其 `initial_phase`；
- 旧主持人 UUID 保留；
- 旧 state revision 保留并为迁移提交增加一次新 revision；
- 不凭空创建离线玩家记录。

### 7.3 有歧义迁移

以下情况不自动猜测：

- 多个健康游戏；
- 旧阶段不是 `IDLE`；
- 初始定义缺失；
- 旧数据损坏；
- 未来未知 Schema。

此时显示迁移诊断，保留原始数据，等待管理员以后执行明确映射或重置。2C 只完成通用迁移框架和开发世界验收，不修改未来正式世界。

## 8. 主持人权限闭环

### 8.1 认领

- 世界没有主持人时，权限等级至少为 2 的 OP 可见认领入口；
- 首次点击只请求确认令牌；
- 确认页显示世界、当前游戏、阶段和权限后果；
- 最终确认成功后原子写入主持人并立即刷新权限快照；
- 不自动选择服主、首个玩家或首个 OP。

### 8.2 转交

- 仅当前主持人可以发起；
- 目标必须是在线玩家，不要求为 OP；
- 目标获得模组主持人权限，但不获得原版 OP；
- 转交原子替换主持人，不能出现无主持人中间状态；
- 转交后双方入口、BossBar 和控制台立即刷新。

### 8.3 接管

- 权限等级至少为 2 的其他 OP 可发起；
- 当前主持人在线或离线均可接管；
- 必须二次确认并显示原主持人、接管者和审计后果；
- 接管成功后旧主持人只失去模组主持人权限。

### 8.4 掉线

- 主持人掉线不自动转交；
- 主持人 UUID 持久保留；
- 主持人离线时 BossBar 没有查看者；
- 其他 OP 可通过接管恢复控制；
- 主持人重连后按当前服务端状态恢复权限。

## 9. 上下文管理员控制台

### 9.1 首页优先级

控制台首页按以下顺序选择首要内容：

1. Schema 或定义阻塞诊断；
2. 无主持人时的认领；
3. 当前活动强制流程进度；
4. 当前阶段可执行的主要操作；
5. 当前阶段值得关注但被禁用的操作；
6. 次级身份工具；
7. 开发与诊断。

页面预览器移动到“开发与诊断”，不再占据主操作按钮。

### 9.2 数据包操作展示

- 按 `section` 和 `order` 稳定排序；
- 重新评估当前阶段、主持人、目标和 predicate；
- 与当前阶段无关的操作不显示；
- 值得关注但暂不可执行的操作显示禁用原因；
- 2C 未开放的操作只在开发诊断中显示能力状态；
- 客户端显示结果不是授权，最终仍由服务端验证。

### 9.3 目标选择

- `none` 直接进入确认；
- `single` 只允许一个目标；
- `multiple` 遵守定义的 `min`、`max` 和 64 人上限；
- 玩家卡沿用 2B 名册视觉；
- 支持在线、身份、流程状态和文本筛选；
- 列表使用现有 Repeat 虚拟化；
- 选择只存在于当前页面实例；
- 最终确认绑定排序后的准确 UUID 集合；
- 目标状态变化时页面刷新，不能使用旧选择绕过筛选。

### 9.4 当前流程页面

显示：

- 流程名称；
- 实例 ID 短标识；
- 创建时间和创建者；
- 完成数、总数和百分比；
- 进行中、未开始、离线、阻塞和已完成分类；
- 查看未完成人员；
- 补充成员；
- 移除成员；
- 取消实例；
- 回调和资源诊断。

## 10. 高风险二次确认

### 10.1 服务端令牌

令牌：

- 由服务端使用安全随机值生成；
- 只保存在服务端内存；
- 有效期 `30 秒`；
- 只能使用一次；
- 同一操作者同时最多一个；
- 打开新确认时旧令牌立即失效；
- 取消、掉线、`/reload` 和服务器重启都会销毁；
- 不持久化，不由数据包生成，不在客户端续期。

### 10.2 绑定内容

令牌绑定：

- 操作者 UUID；
- 操作类型和操作 ID；
- 排序后的准确目标 UUID；
- 活动游戏和阶段；
- definition generation；
- 相关状态 revision；
- 相关目标状态摘要；
- 冻结的标题和后果文本；
- 过期时间。

使用全局 revision 之外，还应计算与操作相关的状态摘要，避免无关玩家的普通变化误伤确认；目标掉线、身份变化、阶段变化和活动实例变化必须使令牌失效。

### 10.3 最终提交

最终确认时重新验证：

- 令牌存在、未过期、未消费；
- 操作者仍在线且仍有权限；
- 活动游戏、阶段、generation 和相关 revision 匹配；
- 面板操作仍可见且可用；
- 目标数量和筛选仍满足；
- 全局单流程不变量仍满足；
- 所有引用和执行能力仍可用。

任一检查失败则不执行任何部分操作，消费或销毁令牌，并返回结构化拒绝原因。

## 11. 强制流程创建

### 11.1 启动前预检

服务端在提交实例前检查：

- 当前操作者是主持人；
- 当前没有未结束强制流程；
- 当前阶段允许来源操作；
- 流程 `required: true`；
- completion policy 合法；
- 受众与显式目标合法；
- 参与者数量为 `1..64`；
- 所有可执行节点属于 2C 支持子集；
- 页面、主题、字段、predicate 和回调可冻结；
- 执行快照未超上限；
- 每个客户端后续都能被独立预检，不把客户端资源当成服务端启动前提；
- 待身份变更没有冲突。

任何失败都不能创建半个实例或半个待身份变更。

### 11.2 名单锁定

- `start_flow` 按流程受众从当前在线玩家锁定名单；
- 显式身份初始化按管理员确认的目标名单锁定；
- `exclude_host`、身份、队伍、生存状态和标签按服务端当前正式状态评估；
- `online_only` 只影响创建时纳入，不使掉线成员退出；
- `if_incomplete` 历史完成者保留为 `already_complete` 并立即计入完成数；
- 0 个实际需要执行的成员时不创建空活动实例；返回“所有目标已完成”结果；
- 后来上线玩家不会自动改变分母。

### 11.3 原子提交

同一次服务端事务提交：

- 实例 ID；
- 锁定名单；
- 成员初始状态；
- 执行快照；
- 待身份变更；
- 首次实例 revision；
- `on_start` 待调用标记；
- 审计事件。

客户端只在该状态成功提交后收到强制页面。

## 12. 运行时节点语义

### 12.1 2C 支持

2C 真实执行：

| 节点 | 支持范围 |
|---|---|
| `page` | 显示冻结页面，接受合法前进动作 |
| `confirm` | 要求页面内明确确认后前进 |
| `choice` | 验证单选值，写入受检字段并路由 |
| `branch` | 仅执行 `scope: player` 的受检 predicate 分支 |
| `complete` | 仅执行 `scope: player` 的自然完成 |

页面内 FieldInput 可随节点提交：

- `scope: flow` 写入当前成员的流程临时字段；
- `scope: player` 在服务端验证后写入玩家持久字段；
- 不存在、不可编辑、类型错误或约束失败的值拒绝整次提交；
- 2C 尚无准备状态，`invalidates_ready` 只保存语义，不执行准备失效。

### 12.2 2C 暂不执行

以下节点仍可注册，但包含它们的流程在 2C 启动预检时被拒绝并给出准确节点 ID：

- `function`；
- `wait_players`；
- `change_state`；
- 任意显式 `scope: event` 节点。

流程级 `on_start`、`on_player_complete` 和 `on_all_complete` 回调仍在 2C 执行。高级节点留到确有正式流程需要时再补语义和回归检查。

### 12.3 请求幂等

每个流程动作请求携带：

- 实例 ID；
- 成员页面实例 ID；
- 流程 ID 和版本；
- 当前节点 ID；
- 冻结 generation；
- 实例 revision；
- 玩家 revision；
- 客户端单调请求序号；
- 动作 ID；
- 有类型字段值。

相同或更旧序号、旧节点、旧 revision 和错误页面实例请求都拒绝。服务端成功处理一次后，重发不能再次推进、再次写字段或再次调用回调。

### 12.4 完成

玩家进入 `complete` 后按顺序：

1. 验证当前游标和请求；
2. 原子标记成员完成；
3. 写入流程 ID + 版本完成记录；
4. 提交绑定该实例的待身份变更；
5. 增加实例 revision；
6. 标记 `on_player_complete` 待调用；
7. 更新 BossBar 和控制台；
8. 如果所有未移除成员已完成，标记实例完成并标记 `on_all_complete` 待调用；
9. 向客户端发送最终状态；
10. 客户端立即解除强制页面。

若同一 tick 多名玩家完成，仍按服务端主线程顺序提交；`on_all_complete` 最多产生一次。

## 13. 名单补充、移除与取消

### 13.1 补充

- 只允许向 `active` 或可恢复的 `blocked` 实例补充；
- 目标必须符合当前来源操作和流程受众；
- 使用实例冻结定义，而不是最新 `/reload` 定义；
- 新成员从入口开始；
- `if_incomplete` 历史完成者直接记为 `already_complete`；
- 已结束或取消实例不能补充；
- 操作必须二次确认并审计。

### 13.2 移除

- 移除不写完成记录；
- 移除取消该成员当前页面实例；
- 清除该成员绑定本实例的待身份变更；
- 分母立即减少；
- 若剩余成员全部完成，正常完成实例并调用一次 `on_all_complete`；
- 操作必须显示对分母和待变更的后果；
- 所有目标及原因进入审计。

### 13.3 全部移除

- 如果最后一个未移除成员也被移除，实例变为 `canceled`；
- 不调用 `on_all_complete`；
- 不创建任何完成记录；
- 清除全部依赖待变更；
- 控制台显示取消原因。

### 13.4 取消实例

- 仅主持人可发起；
- 必须二次确认；
- 取消所有未结束成员页面；
- 清除所有依赖待变更；
- 保留已经自然完成者的历史完成记录；
- 不回滚已经成功调用的外部函数；
- 取消后可以在同阶段发起下一个流程。

## 14. 身份变更事务

### 14.1 猎人初始化

- 主持人可在通用初始化前选择一名或多名玩家；
- 二次确认成功后创建待猎人身份变更和猎人流程实例；
- 正式身份在完成前保持不变；
- TAB 不提前显示猎人；
- `always` 要求已有猎人也重新完成；
- 每名玩家自然完成后独立提交其正式猎人身份；
- 一个成员失败不回滚其他已经完成成员；
- 身份成功变化后相关客户端和控制台立即刷新；
- 2C 尚无准备状态，因此只记录未来需要失效的语义。

### 14.2 活动流程冲突

- 任意强制流程未结束时，不允许再发起猎人初始化；
- 通用初始化进行中不能插入身份初始化；
- 管理员必须先完成、调整名单或取消当前实例；
- 这条规则取代早期“后发流程进入持久队列”的设想。

### 14.3 立即设为旁观者

2C 允许 `assign_role` + `immediate`：

- 只能通过已注册、已确认的主持人操作；
- 当前不能有未结束强制流程；
- 目标必须满足操作筛选；
- 正式身份一次提交；
- 历史流程完成记录保留；
- 不创建身份初始化流程；
- 不提前实现队伍或生存状态联动。

## 15. 强制玩家界面

### 15.1 正常状态

- 服务端存在该玩家未完成成员记录时，客户端显示冻结当前节点页面；
- 页面不能通过 Esc、关闭按钮、背包、聊天或其他模组入口替换；
- 强制页面不暂停世界或集成服务器；
- 合法提交前不能前进；
- 服务端确认最后节点完成后立即关闭并恢复正常游戏；
- 2C 不建设复杂的“流程暂停层”；
- 不存在玩家级下一流程队列，因此完成后不会跳入另一个强制流程。

### 15.2 重连

- 玩家掉线不算完成；
- 离线成员继续保留在分母；
- 重连握手后服务端下发当前实例、节点和冻结页面；
- 客户端恢复上次节点，不重播已经完成节点的回调；
- 玩家名称变化只更新最近名称，不改变 UUID 记录。

### 15.3 安全例外

必需资源、页面快照或客户端渲染异常时：

- 显示模组内置安全错误页；
- 允许重试资源检查；
- 允许查看有界诊断；
- 允许断开连接；
- 向主持人显示该玩家处于 `blocked` 及具体原因；
- 不把客户端错误标记为完成；
- 不允许切换到最新定义偷偷修复当前实例。

2C 实现时必须同步修订 `DATA-PACK-UI-2B.md` 中早期“强制页面可进入安全暂停菜单”的占位描述，以本节已确认语义为准。

## 16. 主持人 BossBar

- 仅当前主持人是查看者；
- 标题使用冻结流程名称、完成数和总数；
- 分母包含离线未移除成员；
- 补充、移除、完成和取消后即时更新；
- 主持人转交或接管后，查看者原子切换；
- 主持人离线时状态保留但无人查看；
- 完成后按冻结 `completion_feedback` 显示并保持定义的 ticks；
- 保持时间结束后移除；
- 因全局只有一个活动流程，`priority` 在 2C 不参与竞争，但继续保留 API 兼容性；
- BossBar 不可点击，“查看未完成”由控制台按钮提供；
- 更新只在值变化时发送，不每 tick 重建。

## 17. 数据包回调

### 17.1 调用顺序

- 核心状态先原子提交，回调随后执行；
- `on_start` 每实例最多一次；
- `on_player_complete` 每名自然完成成员最多一次；
- `on_all_complete` 每实例最多一次；
- `already_complete` 不重复调用 `on_player_complete`；
- 移除成员不调用完成回调；
- 全部移除导致取消时不调用 `on_all_complete`。

### 17.2 上下文

优先使用原版函数宏参数传递冻结上下文：

```text
game_id
flow_id
flow_version
instance_id
player_uuid
player_name
completed
total
state_revision
```

玩家回调以对应玩家作为执行实体；实例级回调使用服务端命令源。不得使用无隔离的全局临时记分板或全局 storage 作为并发参数通道。

### 17.3 失败

- 回调失败不回滚已经提交的核心状态；
- 失败不会自动重复调用；
- 记录函数 ID、实例、玩家、异常和时间；
- 主持人可通过二次确认执行“仅重试回调”；
- 重试不重新完成流程，不重复修改核心状态；
- 外部函数已经产生的世界副作用不承诺回滚；
- 数据包函数不能直接写模组存档，只能使用以后开放的受控接口。

## 18. 执行快照、Reload 与重启

### 18.1 冻结内容

实例创建时冻结：

- 流程定义；
- 实际引用的页面；
- 实际引用的主题；
- 实际引用的字段 Schema；
- predicate 引用；
- 回调引用；
- 文本和声音引用清单；
- 来源操作及确认后果摘要；
- definition generation 和内容哈希。

快照保存规范化源文档和哈希；重启后使用同一严格编译器重新编译，不持久化 JVM 对象。

### 18.2 上限

2C 初始硬上限：

| 项目 | 上限 |
|---|---:|
| 活动强制流程实例 | `1` |
| 实例参与者 | `64` |
| 流程节点 | 沿用 2A 的 `256` |
| 快照引用页面 | `64` |
| 快照引用主题 | `8` |
| 快照规范化 UTF-8 总量 | `2 MiB` |
| 单成员流程字段编码 | `64 KiB` |
| 单确认令牌目标 | `64` |
| 单操作者待确认令牌 | `1` |
| 确认令牌有效期 | `30 秒` |
| 单次诊断明细 | `50` |

超限时拒绝启动，不截断可执行语义。

### 18.3 `/reload`

- 新定义完整验证成功后发布新 generation；
- 当前实例继续使用冻结快照；
- 当前页面不热替换；
- 新发起实例使用最新健康 generation；
- `/reload` 清空确认令牌；
- `/reload` 不修改实例、成员、进度、身份和完成历史；
- 如果数据包删除当前流程，活动实例仍可继续；
- 2C 尚不提供实例显式迁移到新 generation。

### 18.4 正常重启

- 正常停服前依赖 Minecraft 世界保存写回最新 SavedData；
- 重启后验证 Schema、快照哈希和引用；
- 成功则恢复实例、成员和页面；
- 失败则进入 `blocked`，不自动使用最新数据包；
- 2C 不建设独立 WAL；突然断电的持久保证与原版世界保存一致；
- “每页立即保存”在 2C 中指服务端主线程立即更新权威 SavedData 并标记 dirty，正常保存和停服会写盘。

## 19. 2C 面板操作能力矩阵

| 操作 | 2C |
|---|---|
| `start_flow` + required flow | 执行 |
| `assign_role` + `after_flow` | 执行 |
| `assign_role` + `immediate` | 执行 |
| 当前实例补充成员 | 系统操作 |
| 当前实例移除成员 | 系统操作 |
| 当前实例取消 | 系统操作 |
| 回调人工重试 | 系统操作 |
| `assign_team` | 仅注册与诊断 |
| `assign_life_state` | 仅注册与诊断 |
| `transition_phase` | 仅注册与诊断 |
| 面板 `run_function` | 仅注册与诊断 |
| 非必需流程并行执行 | 不支持 |

未开放能力不能调用一部分后再失败。

## 20. 网络协议 v7

### 20.1 新增能力

协议 v7 至少覆盖：

- 主持人系统状态；
- 控制台上下文目录；
- 目标选择快照；
- 确认请求、令牌返回、取消和最终提交；
- 活动流程摘要；
- 未完成成员分页；
- 强制页面打开与节点状态；
- 流程动作提交和结果；
- 资源错误上报；
- 主持人认领、转交和接管；
- 实例补充、移除和取消；
- 回调重试；
- 审计与诊断摘要。

### 20.2 通用信封

所有有状态请求包含：

- 协议版本；
- 客户端请求序号；
- 操作者 UUID 由连接推导，不接受客户端自报；
- 活动游戏 ID；
- definition generation；
- 相关实例 ID；
- 相关页面实例 ID；
- 服务端状态 revision；
- 操作或动作 ID；
- 有界参数。

### 20.3 拒绝代码

至少提供稳定代码：

```text
forbidden
not_host
host_already_assigned
target_offline
target_invalid
target_count_invalid
phase_mismatch
definition_generation_stale
state_revision_stale
confirmation_missing
confirmation_expired
confirmation_consumed
confirmation_context_changed
active_flow_exists
flow_not_active
flow_instance_mismatch
node_mismatch
request_replayed
unsupported_operation
unsupported_flow_node
snapshot_too_large
snapshot_invalid
resource_blocked
callback_failed
schema_blocked
rate_limited
```

拒绝响应带用户可读说明，但客户端不能根据说明文本推断授权。

### 20.4 限频与大小

- 控制台刷新合并同 tick 重复请求；
- 目标名单最大 64；
- 未完成名单分页或有界下发；
- 确认请求、最终提交和流程动作分别限频；
- 重复包幂等拒绝；
- 服务端不回显任意客户端 JSON；
- 页面和主题继续使用 v5 已有按需缓存机制；
- 协议不兼容时强制流程不能假装完成。

## 21. 实施顺序

以下顺序是依赖边界，不强制对应同名类：

1. 写 2C 自检夹具和 Schema v2 纯数据模型；
2. v1 → v2 迁移及恢复快照；
3. 主持人认领、转交、接管；
4. 玩家记录、完成历史和待身份事务；
5. 执行快照编译与大小上限；
6. 单活动流程运行器；
7. 节点动作验证与幂等；
8. 回调和失败诊断；
9. BossBar；
10. 网络协议 v7；
11. 上下文控制台、目标选择和确认页；
12. 强制客户端页面与重连恢复；
13. 短流程验收夹具；
14. 独立服务端、开发客户端和异常恢复验收；
15. 文档与收口记录。

每一步复用现有 2A 编译结果、2B 页面渲染器、ConsoleButton、玩家名册和导航转场。不得建设第二套定义解析器、页面渲染器或权限状态。

## 22. 自动检查矩阵

### 22.1 Schema 与迁移

- 新世界创建 v2；
- v1 IDLE + 唯一游戏自动迁移；
- v1 非 IDLE 阻塞；
- 多游戏阻塞；
- 未知未来 Schema 保留原始数据；
- 迁移失败不覆盖；
- 主持人和 revision 正确保留；
- 恢复快照可读取且校验哈希。

### 22.2 主持人

- 无主持人时 OP 可认领；
- 非 OP 不可认领；
- 已有主持人时重复认领拒绝；
- 主持人可转交在线非 OP；
- 离线目标拒绝；
- OP 可接管；
- 转交和接管原子；
- 掉线不清除主持人；
- 重启后保持。

### 22.3 确认令牌

- 30 秒边界；
- 单次消费；
- 取消销毁；
- 新令牌替换旧令牌；
- 操作者绑定；
- 目标集合绑定；
- 阶段、generation、revision 和相关状态绑定；
- 无关状态变化不误伤；
- 目标变化正确失效；
- `/reload`、掉线和重启清空；
- 过期请求不产生部分状态。

### 22.4 单活动流程

- 无活动实例时成功创建；
- 活动实例存在时第二次启动拒绝；
- 完成后同阶段可再启动；
- 取消后可再启动；
- 阶段推进在实例活动时拒绝；
- 0、1、32、64 人名单；
- 65 人拒绝；
- later join 不改变分母；
- 掉线不改变分母；
- 重复启动幂等。

### 22.5 完成策略

- `if_incomplete` 跳过同版本完成者；
- 新版本重新要求完成；
- `always` 强制历史完成者重做；
- `resume_only` 不创建新实例；
- 当前实例内重复 `always` 请求拒绝；
- `already_complete` 不调用玩家完成回调。

### 22.6 节点

- page 正常前进；
- confirm 必须显式确认；
- choice 类型、选项和路由；
- player branch predicate；
- flow 字段保存；
- player 字段保存；
- 不可编辑和非法字段拒绝；
- unsupported 节点启动前拒绝；
- 旧节点、旧页面实例和旧 revision 拒绝；
- 重复请求不推进两次。

### 22.7 身份事务

- 目标完成前正式身份不变；
- 完成后原子变更；
- 多目标分别完成；
- 移除清除待变更；
- 取消实例清除未完成待变更；
- 已完成玩家不被后续取消回滚；
- 已有猎人通过 `always` 重做；
- 活动流程存在时新身份操作禁用；
- immediate 旁观者操作在无活动流程时成功。

### 22.8 名单调整

- 补充玩家从入口开始；
- if_incomplete 补充者正确跳过；
- 移除不写完成；
- 移除后分母更新；
- 移除导致剩余全完成时触发一次全部完成；
- 全部移除标记取消；
- 结束实例不允许补充；
- 操作者、目标、原因和时间进入审计。

### 22.9 回调

- 三类回调最多一次；
- 玩家上下文正确；
- 实例上下文正确；
- 回调失败不回滚核心状态；
- 失败不自动重试；
- 人工重试不重复完成；
- 移除和全部取消不误调用；
- 宏参数不经全局临时状态串线。

### 22.10 Snapshot 与 Reload

- 当前实例冻结 generation；
- `/reload` 后当前页面不变；
- 新实例使用新 generation；
- 删除当前数据包定义后活动实例继续；
- 正常重启恢复节点；
- 哈希错误进入 blocked；
- 超过 2 MiB 启动拒绝；
- 完成和取消后删除完整 UI 快照；
- 活动实例不存在时不保留大文档。

### 22.11 网络与权限

- 所有新 payload 编解码边界；
- 超长文本、过多目标和过大包拒绝；
- 非主持人伪造操作拒绝；
- 客户端伪造 UUID 无效；
- 请求序号回放拒绝；
- 跨实例和跨页面请求拒绝；
- 协议 v5 客户端不能进入 v6 强制流程；
- 限频不会阻断正常一次操作。

## 23. 实机验收计划

### 23.1 基础链路

1. 完全重启开发服务端和客户端；
2. 进入开发世界；
3. OP 从 ESC 控制台认领主持人；
4. 打开当前阶段首页；
5. 在“开发与诊断”确认六个旧页面仍能预览，但不会成为活动流程页面；
6. 发起 `pixel_tzz:start_general_initialization`；
7. 确认来源操作显示 `if_incomplete`，活动页面依次为 `fixture/general/briefing` 与 `fixture/general/confirm`；
8. 目标玩家完成说明与明确确认；
9. 主持人 BossBar 变为完成；
10. 页面立即解除；
11. 阶段保持不变；
12. 再次发起时，当前版本已有完成记录的玩家不重复打开。

### 23.2 猎人

1. 选择一名或多名玩家；
2. 检查确认页目标和后果；
3. 发起 `pixel_tzz:assign_hunter`，确认操作显示 `always`；
4. 完成前 TAB 仍显示旧身份；
5. 分别完成 `fixture/hunter/briefing` 与 `fixture/hunter/confirm`；
6. 每人完成后正式变为猎人；
7. 重新对已有猎人发起，确认 `always` 生效。

### 23.3 全局单流程

1. 保持一个成员未完成；
2. 尝试发起第二流程；
3. 确认按钮禁用且说明当前实例；
4. 尝试阶段推进；
5. 确认服务端拒绝并展示未完成名单；
6. 完成当前实例；
7. 在同阶段成功发起下一流程。

### 23.4 掉线和重启

1. 玩家停在中间节点掉线；
2. BossBar 分母不变；
3. 重连后恢复节点；
4. 再次停在中间节点；
5. 正常关闭服务端；
6. 重启后恢复相同实例和节点；
7. 已完成回调不重复。

### 23.5 Reload

1. 活动实例停在中间节点；
2. 修改验收夹具文案并 `/reload`；
3. 当前玩家继续看到旧快照；
4. 完成当前实例；
5. 再次发起后看到新 generation；
6. 主持人、身份和完成历史不变。

### 23.6 名单调整

- 补充在线玩家；
- 移除离线玩家；
- 移除含待猎人变更的玩家；
- 移除后剩余全完成；
- 全部移除；
- 取消整个实例；
- 核对分母、页面解除、待变更和审计。

### 23.7 令牌异常

- 等待服务端令牌自然过期，并确认同一次点击会透明重取后只执行一次；
- 打开新确认使旧令牌失效；
- 确认前使目标掉线；
- 确认前改变目标身份；
- 确认前 `/reload`；
- 双击最终确认；
- 重放抓取的旧请求；
- 自然过期且上下文不变时允许新令牌完成一次操作；其余情况均不得部分执行。

### 23.8 资源与快照异常

- 缺失可选资源；
- 缺失必需资源；
- 客户端资源预检失败；
- 服务端快照哈希故意损坏；
- 恢复原资源后重试；
- 玩家不能被错误标记完成；
- 主持人能看到准确诊断。

### 23.9 UI

- UI 完成度不低于 2B 当前控制台和玩家名册；
- 中文主标题、英文辅助标签层级正确；
- Compact、Standard、Wide 无溢出；
- 64 人目标选择滚动稳定；
- 按钮悬停不移动命中区域、不播放悬停音；
- 二次确认清楚展示操作、目标、阶段、后果和可撤销性，不显示内部令牌剩余时间；
- 前进、返回和关闭转场方向一致；
- 强制页面完成后自然解除，不出现黑帧或世界闪烁；
- 音效不重叠。

## 24. 性能与资源要求

- 32 人为正常目标，64 人为压力目标；
- 单成员提交不得重建所有其他成员页面；
- BossBar 仅在值变化时同步；
- 控制台目录和名单按 revision 增量刷新；
- 不每 tick 序列化完整执行快照；
- 冻结快照只在实例创建时构建一次；
- 页面仍按需下发和缓存；
- 审计、诊断和拒绝日志有界；
- 完成或取消后释放客户端页面订阅和服务端大快照；
- 不新增第三方依赖；
- 不增加第二套表达式、predicate 或页面执行器。

## 26. 完成定义

2C 只有同时满足以下条件才收口：

1. Schema v2、迁移和恢复快照安全；
2. 主持人权限闭环通过；
3. 上下文控制台执行真实操作；
4. 二次确认令牌抗过期、重放和状态变化；
5. 全局同时只有一个强制流程；
6. 页面节点、字段和完成记录由服务端权威执行；
7. 掉线、正常重启和 `/reload` 不丢进度；
8. 猎人 `after_flow` 身份事务正确；
9. immediate 旁观者操作正确；
10. BossBar 和未完成名单正确；
11. 回调失败不破坏核心状态；
12. 所有未开放操作失败关闭；
13. 64 人压力测试性能有界；
14. 用户完成真实客户端验收；
15. 正式教程、准备、开局、捕获和运镜仍未提前实现。

完成后停止，不自动进入准备与开局里程碑，也不开始编写正式数据包流程。
