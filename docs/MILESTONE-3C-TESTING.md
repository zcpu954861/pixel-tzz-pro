# V3C 数据驱动 HUD 与正式开局倒计时实机验收手册

状态：**测试计划已冻结；实现与自动验证已完成，全部五客户端项目等待实机验收**

- 编写日期：2026-08-04
- 目标模组版本：`0.1.0`
- Minecraft：`26.2`
- 目标游戏 API：v4
- 目标网络协议：v13
- 目标世界状态：Schema v5

## 1. 使用方式

本手册供 V3C 实现收口后的逐项五客户端验收使用。文中的
`pixel_tzz:acceptance_3c/*` 函数和资源已随实现加入示例数据包，但应在完整自动检查通过后再
作为实机验收入口。

验收节奏：

1. 主代理一次只给用户一项测试，必要的 `/reload` 与触发函数应在同一条消息一次说全；
2. 用户回复 `PASS` 或提供截图、客户端、现象与顺序；
3. 一轮中发现的问题全部记录，用户明确结束该轮后集中修复；
4. 修复后只回归受影响项和必要前置项；
5. 自动检查、日志无异常和客户端成功启动都不能替代真实画面、声音与多人同步；
6. 用户没有明确反馈的项目始终保持“未测试”；
7. 用户确认全部问题通过前，不提交、不推送、不合并。

每项只有一个通过标准。任一客户端看到越权字段、额外 HUD、闪烁、重播、重复声音、半截控件、
错误倒计时或机器诊断，该项不能记为通过。

失败时至少记录：

- 项目编号与客户端；
- 屏幕分辨率、GUI Scale、F1/TAB/聊天/Screen 状态；
- 操作前布局、触发命令、操作后布局；
- 是否首次打开、后台刷新、Reload 或重连后发生；
- 倒计时实例 ID、状态、剩余 Tick 和状态版本；
- `logs/latest.log` 对应时间附近首个异常；
- 是否可稳定复现，以及其他客户端是否同时看到。

## 2. 自动检查与实机边界

### 2.1 实机开始前的目标自动门

实机开始前，以下 V3C 自动门已注册并必须保持通过：

```powershell
.\gradlew.bat hudDefinitionSelfCheck
.\gradlew.bat hudRouteClosureSelfCheck
.\gradlew.bat hudProjectionCompilerSelfCheck
.\gradlew.bat hudMinecraftBindingSourceAccessSelfCheck
.\gradlew.bat hudPreviewBindingSourceAccessSelfCheck
.\gradlew.bat hudPreviewServerRuntimeContractSelfCheck
.\gradlew.bat hudSnapshotProtocolSelfCheck
.\gradlew.bat hudLayoutPolicySelfCheck
.\gradlew.bat hudAnimationLifecycleSelfCheck
.\gradlew.bat hudClientPreferencesSelfCheck
.\gradlew.bat countdownDefinitionSelfCheck
.\gradlew.bat countdownAuthoritySelfCheck
.\gradlew.bat countdownRestrictionSelfCheck
.\gradlew.bat countdownPersistenceSelfCheck
.\gradlew.bat countdownCallbackLedgerSelfCheck
.\gradlew.bat protocolV13SelfCheck
.\gradlew.bat clean check build --console=plain --no-daemon
git diff --check
```

这些 V3C SelfCheck 已接入 `check.dependsOn`；单项通过仍不能替代 Minecraft 实机验收。

### 2.2 自动检查能证明什么

自动检查应证明：

- 严格 JSON、覆盖、引用 DAG、降级闭包与错误隔离；
- 路由唯一性与同优先级冲突；
- 根、组件、字段、数据源和上下文受众交集；
- v13 Replace/Patch/Clear 顺序、大小、乱序与重同步；
- Schema v5 迁移、倒计时状态机、限制幂等和回调至多一次；
- 无倒计时 API v3/v4 Game 的 2D 兼容；
- 客户端偏好范围、锁定、草稿序列化和未知组件迁移。

自动检查不能证明：

- 右下角是否真正自然、不抢视线；
- 赛程脊线、中文、头像、进度条和倒计时是否美观；
- HUD 是否与热键栏、ActionBar、声音字幕、聊天和其他模组重叠；
- 更新是否在真实帧率下闪烁或重播动画；
- 五端音画是否同步；
- 低 FPS、拖动窗口和 GUI Scale 是否破坏比例；
- 玩家设置是否好用。

## 3. 环境与固定分工

## 4. A 组：资源、版本与权限

### 3C-01 安装、协议与旧世界基线

目标：确认 v13、Schema v5 和示例资源实际加载。

操作：

1. 启动 Player972 世界；
2. 五客户端依次进入；
3. 执行实现后的 `acceptance_3c/setup` 与 `/reload`；
4. 打开主持人资源诊断和普通玩家 ESC。

通过标准：

- 五端握手为 v13，无客户端被静默降级为错误协议；
- 世界迁移到 Schema v5 且 V3A/V3B 数据保留；
- 主持人看到 HUD/Profile/Countdown 资源已加载；
- 普通玩家没有资源路径、红字或管理员诊断；
- `/reload` 不清玩家身份、准备、终端历史或 V3B 偏好。

### 3C-02 有效、无效与上一代恢复

目标：验证严格解析和 generation 原子发布。

操作：依次加载有效夹具、单组件未知键、引用环、Profile 路由平局和 required Countdown 缺失
Layout；每次 `/reload` 后查看资源诊断和当前 HUD。

通过标准：

- 每个错误定位到正确资源与引用链；
- 非 required HUD 错误按闭包隔离或降级；
- required Countdown 错误阻止批准；
- 当前有效 HUD 不因失败 Reload 消失或闪一下；
- 普通玩家只看到稳定旧版本或安全无 HUD。

### 3C-03 单根路由与平局

目标：确认 task → context → default → none 的唯一选择。

操作：依次切换无任务、context 身份、活动 task、结束 task，并触发一个运行时不可静态证明的
同优先级平局夹具。

通过标准：

- 每次只有一个常驻根布局；
- task 路由覆盖 context，结束后正常回到 context/default；
- 不出现两个信息坞或字段拼接；
- 平局 fail closed 并给主持人诊断，不按 JSON 第一项选择。

### 3C-04 最小权限投影与非主持人 OP

目标：验证受众求交和 OP 不提权。

操作：让 B 为猎人、C/D/E 为逃走者；分别注册猎人、逃走者、主持人与公开字段；给 C 临时 OP
但不接管主持人。

通过标准：

- 每端只见对应组件和值；
- C 成为 OP 后仍只见逃走者 HUD；
- Player972 不因命令执行者身份收到目标玩家 HUD；
- 网络/客户端日志中不存在被隐藏字段的正文或真实值；
- 正式接管主持人只改变管理权限，不把主持人开发预览常驻到普通 HUD。

### 3C-05 权限撤销立即清理

目标：敏感内容不能使用 stale。

操作：B 正在查看猎人专属字段时改变其身份/受众，随后恢复；在网络延迟与 Screen 打开状态下各
执行一次。

通过标准：

- 撤权后一帧级原子替换或 clear；
- 不显示旧值、占位暗示、淡出残影或上一布局背景；
- 恢复权限时只显示最新值；
- 其他不相关组件不重播进入动画。

## 5. B 组：默认信息坞与视觉层级

### 3C-06 右下角默认构图

目标：验收首版正常信息坞。

操作：2K 基准窗口、GUI Scale 4，显示任务标题、正文、进度、计时与两个次要字段。

通过标准：

- 信息坞位于右下安全区域，底边稳定、内容向上生长；
- 不覆盖热键栏、经验条、ActionBar 或声音字幕；
- 赛程脊线清晰但不过度抢眼；
- 没有三四层重复外框或一堆等权信息卡；
- 中文主次明确，英文仅作弱化衬托；
- 用户确认首版视觉可以进入后续逐项微调。

### 3C-07 空组件、空布局与收缩

目标：不存在“没有内容但留一个框”。

操作：逐个移除次要字段、进度、任务正文和最终标题，随后全部恢复。

通过标准：

- 子组件消失时 gap 同步收起；
- 只剩一个字段时不保留原大高度；
- 全部组件隐藏时无边框、阴影、脊线或透明占位；
- 恢复只播放一次真实进入，不周期闪烁。

### 3C-08 长中文、Emoji、长玩家名和重复列表

目标：验证真实字体布局和摘要。

操作：使用长任务名、两段中文正文、Emoji、长玩家名、超过上限的公开目标列表。

通过标准：

- 文字按声明换行/省略，不越过边框；
- Emoji 不拆成乱码方块造成测量错位；
- 玩家名不会挤掉 critical 任务信息；
- repeat 只显示上限项目和明确剩余摘要；
- 不出现滚动条；
- 正文更新时信息坞底边不跳动。

### 3C-09 进度、计时与状态变化

目标：数值更新平滑但不伪造状态。

操作：缓慢推进进度、瞬间跨越阈值、暂停/继续任务、切换状态 Badge。

通过标准：

- 进度条平滑追随且不超过权威值；
- 任务完成时直接落到最终值，不因插值延迟业务完成；
- 计时以分秒显示，不出现原始 Tick；
- 暂停标记准确，继续后无跳秒；
- Badge 未知值不显示注册键。

### 3C-10 正常、紧凑、摘要与降级

目标：空间不足按固定语义降级。

操作：逐步缩窄窗口并添加排除区域，观察 normal → compact → summary → degradation。

通过标准：

- 每次只切换一次，状态稳定后不来回抖动；
- compact 是语义摘要，不是所有内容缩成小字；
- critical 内容始终完整；
- decorative/secondary 只在获准时隐藏；
- 无合法布局时安全清空并给主持人诊断，不绘制半个组件。

### 3C-11 窗口、全屏与 GUI Scale

目标：所有页面/组件按同一比例体系工作。

操作：测试 2560×1440 基准、1920×1080、1280×720、窄窗口、全屏切换，以及可用 GUI Scale。

通过标准：

- 2K 基准比例与计划线框一致；
- 小窗口整体等比缩小，不单独放大按钮、文字或进度内部；
- 大屏不无限变大；
- 拖动窗口时无越界、裁切和坐标漂移；
- 排除区域、拖动预览和真实 HUD 使用同一坐标系。

## 6. C 组：安全区、Screen 与刷新

### 3C-12 原版 HUD 安全区

目标：验证热键栏、ActionBar、BossBar、聊天和声音字幕避让。

操作：分别显示经验条、BossBar、长 ActionBar、展开聊天、开启声音字幕并制造多条字幕。

通过标准：

- 信息坞不盖住任一原版关键信息；
- 只在必要时向上/向内避让或进入紧凑态；
- 原版元素消失后平滑回到稳定位置，不播放全新进入动画；
- 不拦截、清除或重写原版内容。

### 3C-13 自定义排除矩形

目标：其他模组没有 API 时仍可手动避让。

操作：在设置中添加、移动、禁用、删除两个排除区域，应用和取消各一次。

通过标准：

- 草稿只影响页面预览，应用后才改变正式 HUD；
- 区域有清晰来源/说明且不能拖出参考画布；
- 重叠区域合并求解不产生无限循环；
- 删除后正确恢复；
- 不读取或修改第三方 HUD 内容。

### 3C-14 F1、TAB、聊天与各类 Screen

目标：验证固定可见性策略。

操作：依次 F1、TAB、打开聊天、ESC、库存、箱子、设置、玩家终端、主持人控制台、数据页和强制
流程页面。

通过标准：

- 正常游戏和聊天输入中显示；
- F1 与列出的 Screen 中隐藏；
- TAB 冲突按本地 policy 调暗/隐藏；
- Screen 关闭后原位恢复，不闪红色旧页面、不重播进入动画；
- 强制页面期间 HUD 不透出敏感内容。

### 3C-15 后台刷新不闪烁

目标：排除定期同步视觉刷新。

操作：HUD 静止观察至少两分钟，同时让服务端正常发送心跳、相同值和时钟校正。

通过标准：

- 文字、蓝色强调、脊线、头像、进度和外框均不闪；
- 无周期进入动画、声音或整体重绘；
- 右上角同步提示只在真实同步事件出现，不随普通 HUD Tick 闪烁。

### 3C-16 原子任务切换

目标：不能混合旧任务与新任务。

操作：让当前任务从 A 原子结算并进入 B，分别在正常游戏、聊天输入和短暂网络延迟下观察。

通过标准：

- 任一帧要么完整 A，要么完整 B；
- 不出现 A 标题 + B 进度、旧身份 + 新数据；
- 真实结构切换只播放一次变化动画；
- V3B 任务提示与 HUD 不互相覆盖或重复同一内容。

### 3C-17 低 FPS、插值与重同步

目标：验证客户端只负责平滑，不影响权威时间。

操作：PlayerC 限制低 FPS，制造一次丢 Patch/重同步和一次超过校正阈值的时钟偏差。

通过标准：

- 其他客户端不受影响；
- C 不爆发播放错过的动画/声音；
- 计时最终与服务端一致，不倒退抖动；
- 只发一次节流重同步请求；
- 重同步 Replace 不重播进入动画。

## 7. D 组：设置与辅助功能

### 3C-18 设置目录与六个子页

目标：验证信息架构。

操作：`选项 → 全员逃走中设置 → HUD 与倒计时`，依次打开全局显示、布局编辑、组件管理、
避让区域、倒计时表现、重置与诊断。

通过标准：

- 上级分类仍为一行两列；
- 六个子页都可达且 ESC 返回上一级；
- 页面使用现有固定参考画布和 3A 视觉语言；
- 没有主页滚动、底部按钮半截或过量空白；
- 只有组件列表的内容区可以独立滚动。

### 3C-19 草稿、应用、取消与离开保护

目标：设置不会边编辑边永久生效。

操作：移动、缩放、改透明度、隐藏允许组件，先取消；再重复并应用；最后有未保存草稿时按 ESC。

通过标准：

- 取消恢复进入页面前状态；
- 应用原子更新且只影响当前客户端；
- 未保存离开有清晰确认；
- 拖动中断、窗口变化和 Screen 关闭不留下半写配置；
- 应用不向服务器发送任意值或改变受众。

### 3C-20 数据包锁定与完全隐藏

目标：每项客户端自由度受数据包独立控制。

操作：依次加载允许完全隐藏、禁止完全隐藏、只允许缩放、只允许两个锚点、部分组件可隐藏的
Profile。

通过标准：

- 控件可用状态与锁定原因准确；
- 禁止隐藏时不能通过透明度 0、移出屏幕或配置文件旧值绕过；
- 允许隐藏时可彻底无 HUD；
- 组件只能在同一 reorder group 内移动；
- policy 收紧立即生效，重新放宽能安全恢复合法旧偏好。

### 3C-21 Full、Simplified、Static 与高对比

目标：辅助功能不改变权威状态。

操作：B/C/D/E 分别使用完整、简化、静态、高对比；同时播放真实 HUD 更新与 Countdown 预览。

通过标准：

- 四端最终内容和值一致；
- 简化移除无必要位移/脉冲；静态无滑入、缩放和闪烁；
- 高对比保持语义且不只靠颜色；
- 倒计时剩余时间与完成 Tick 完全一致；
- 数据包不能强制恢复完整动画。

### 3C-22 独立音量、持久化与重置

目标：HUD/Countdown 音量独立且本地持久。

操作：分别调整 HUD 与倒计时音量，重启单个客户端；执行 scoped reset，再执行全部 V3C 偏好 reset。

通过标准：

- 两类音量互不影响，也不改变 V3B 字符音量；
- 设为 0 时无对应声音但权威时序正常；
- 重启后偏好恢复；
- reset 明确显示范围，不清世界数据或其他玩家偏好；
- 旧/未知组件配置被隔离而非错套。

### 3C-23 普通预览与主持人开发预览

关键秒。

- 主持人预览只在本机出现；
- 不执行函数、不写历史、不发声音给他人、不创建正式 Countdown；
- 关闭预览后正式 HUD 原位保持；

## 8. E 组：正式开局倒计时

### 3C-24 无 Countdown 的 2D 兼容

目标：旧数据包不被强制倒计时。

操作：使用 `api_version: 3` 或 v4 但省略 `opening_countdown` 的 Game，走完整玩家准备和主持人批准。

通过标准：

- 批准仍按 2D 立即原子启动首个环节；
- 不出现中央空倒计时、额外 Subtitle 或声音；
- 现有任务、回调、BossBar、终端和 V3B 提示回归正常。

### 3C-25 required 无效阻断与 optional 降级

目标：required 语义明确。

操作：同一缺失 Countdown/Layout 分别以 `required: true` 和 `false` 批准。

通过标准：

- required 时确认页明确显示阻断资源显示名与影响，无法批准；
- optional 时主持人明确审阅“将无倒计时立即开局”后才能批准；
- 不加载半个 Countdown；
- 普通玩家不看到资源路径。

### 3C-26 五端倒计时音画同步

目标：首个完整正式倒计时。

操作：五端回到正常游戏画面，主持人批准 10 秒 Countdown，观察起点、5、3、2、1、0 与完成。

通过标准：

- 五端使用同一权威剩余时间，低延迟下视觉误差不超过可接受帧差；
- 中央布局有上限，不遮全屏；
- checkpoint 声音每端每点只播放一次；
- 不因本地设置产生额外倒计时或延迟完成；
- 0 后只进入一次热身；
- 常驻信息坞与中央 Countdown 不形成两个互相抢夺的主焦点。

### 3C-27 限制、镜头、聊天与 ESC

目标：默认限制完整且不过界。

操作：Countdown 中尝试移动、跳跃、攻击、交互、使用/丢弃/交换物品、打开库存、受伤、转镜头、
聊天和 ESC。

通过标准：

- 声明阻止项全部被服务端拒绝，无客户端预测残留；
- 临时伤害免疫生效；
- 镜头、第三人称、聊天和 ESC 可用；
- 不改游戏模式、不出现永久效果或无关属性变化；
- 完成/取消后限制一次性完整解除。

### 3C-28 主持人取消与状态版本确认

目标：取消安全且无二次错误闪窗。

操作：Countdown 中打开主持人控制台，发起取消确认；一轮直接确认，一轮先让状态变化再确认，
一轮等待令牌过期。

通过标准：

- 确认写明操作、Countdown、剩余时间、保留项、丢弃项和回调不可回滚部分；
- 正常确认回到等待批准并保留准备/字段；
- 状态变化或过期时只显示一次重新审阅入口；
- 重新审阅直接打开最新确认，不弹第二个无关错误；
- 没有跳过/快进按钮。

### 3C-29 required player 的 pause/cancel/continue

目标：三种策略使用冻结 UUID 且互不混淆。

操作：分别启动三个夹具，在剩余约 6 秒时退出 PlayerC，并按策略重连/观察。

通过标准：

- pause：所有端剩余时间冻结，C 同 UUID 返回协调后无缝继续；
- cancel：正式取消并回到等待批准；
- continue：其他端继续，C 不被从冻结参与者移除；
- 任何策略都不扩大受众、不自动换人、不重复 start callback；
- 缺失原因普通玩家只见公开摘要，主持人可见具体名单。

### 3C-30 主持人掉线与接管

目标：默认主持人掉线不影响倒计时。

操作：Player972 在 Countdown 中退出，观察 B-E；随后以合法流程接管主持人并取消另一轮。

通过标准：

- 默认 continue 不暂停、不重启、不重复声音；
- 普通 OP 不自动获得取消入口；
- 正式接管后新主持人可见同一 Countdown 状态；
- 接管不重建实例或改变冻结参与者；
- 配置 pause/cancel 的定向夹具按声明工作。

### 3C-31 `/reload` 冻结 generation

目标：活动 Countdown 不被热重载替换。

操作：Countdown 中修改下一代 duration、Layout、声音与 callback，执行一次 `/reload`，随后完成
当前轮并再次批准下一轮。

通过标准：

- 当前轮继续原冻结时长、布局、声音和 callback；
- Reload 本身不取消、不跳秒、不重播进入；
- 下一轮才使用新有效 generation；
- 无效新 generation 保留上一代有效目录；
- 回调账本不重复。

### 3C-32 服务器正常重启与 recovery wait

目标：离线时间不计入倒计时。

操作：剩余约 7 秒正常保存退出世界/服务器，等待明显长于 7 秒，再启动；先只让主持人进入，随后
按顺序让参与者进入。

通过标准：

- 恢复到 `recovery_wait`，剩余仍约 7 秒；
- 客户端未完成协调时不倒数；
- 条件满足后从同一实例继续；
- 不重播 start callback 和已过 checkpoint 声音；
- 冻结快照故障夹具 fail closed，有安全取消入口而不立即开局。

### 3C-33 callback 至多一次与失败重试

目标：多步 start/pause/resume/cancel/complete 回调可恢复。

操作：让 `complete` 的一个 global 与一个逐玩家 callback 成功，另一个故障；修复故障后重试，
期间执行 Reload/重连各一次。

通过标准：

- 已成功项不重放；
- 只重试失败项且宏上下文仍是冻结实例；
- required 未完成前不启动热身；
- 完成后只启动一次；
- canceling/completing 不回到 running 重播最后几秒；
- 预览与网络重同步不创建 ledger 条目。

### 3C-34 热身与全局游戏时长

目标：最终时序完全符合确认。

操作：批准 → Countdown → warmup → 完成 warmup → first main；分别记录 countdown、warmup task、
game、main task 时钟。

通过标准：

- Countdown 完成前不进入 warmup；
- warmup 在 Countdown 后开始，有自己的时钟；
- Countdown 与 warmup 期间 `game_elapsed_ticks` 不增加；
- warmup 完成后 game clock 与 first main 同一权威提交开始；
- 无 warmup Game 在 Countdown 完成时直接同时启动 game/main；
- HUD 全程显示人类可读分秒，不把 Tick 暴露给普通玩家。
